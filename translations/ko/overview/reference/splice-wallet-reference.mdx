Splice Wallet은 Canton Network의 모든 Validator Node에 내장된 wallet component입니다. Web UI, background automation, programmatic API를 포함해 해당 Validator에서 hosting하는 Party의 Canton Coin(CC) management를 제공합니다.

## Wallet UI

Wallet UI는 모든 Validator Node와 함께 제공되며 사용자에게 CC operation을 위한 browser-based interface를 제공합니다. Login하고 새 Party가 allocate되는 onboarding을 마친 사용자는 다음을 수행할 수 있습니다.

- CC balance와 개별 Holding contract(UTXO) 확인
- Transfer offer 또는 one-step preapproved transfer를 통해 다른 Party에 CC 전송
- Incoming transfer offer accept, reject 또는 withdraw
- Transaction history 검토
- Network의 모든 Validator를 위해 Traffic 구매
- Minting delegation 관리, External Party proposal accept/reject/withdraw

Validator operator Party는 Validator initialization 중 자동으로 생성되고 configured `validatorWalletUser`와 연결됩니다. 다른 User는 UI 또는 `/v0/admin/users` API endpoint를 통해 onboarding합니다.

## Wallet Automation

Validator App은 Wallet User를 대신해 여러 background automation을 실행합니다. 이를 통해 수동 개입 없이 recurring CC operation을 처리합니다.

**Reward collection.** Wallet automation이 onboarding된 각 Party의 reward coupon(Validator reward, app reward, liveness activity record)을 주기적으로 collect하고 mint합니다. Earned coupon을 CC Holding으로 변환합니다.

**Traffic top-up.** 설정된 경우 extra Traffic balance가 threshold 아래로 내려가면 Validator가 operator wallet의 CC로 Traffic Credit을 자동 구매합니다. Operator가 `targetThroughput`과 `minTopupInterval`을 설정하면 automation이 해당 throughput을 유지하기에 충분한 Traffic을 구매합니다. DevNet에서는 wallet에 fund가 부족하면 Validator가 충분한 coin을 자동 tap합니다.

**Sweep.** Operator는 sender balance가 `maxBalanceUSD` threshold를 초과할 때 한 Party에서 다른 Party로 CC를 transfer하는 automatic sweep을 설정할 수 있습니다. Automation은 fund를 configured `minBalanceUSD`까지 낮추는 transfer offer를 생성합니다. Sweep configuration은 Sender Party ID를 Receiver Party ID와 balance threshold에 mapping합니다. Sweep은 one-step delivery를 위해 Transfer Preapproval을 사용할 수 있습니다.

**Auto-accept.** Operator는 특정 Sender Party의 incoming transfer offer를 자동 accept하도록 설정할 수 있습니다. Validator Helm chart 또는 Docker Compose configuration에서 Sender-Receiver Party ID pair별로 설정합니다.




## Transfer Workflow

Party 간 CC transfer는 세 pattern 중 하나를 따릅니다.

**Two-step Token Standard transfer.** Sender가 CC를 `TransferInstruction` contract에 lock합니다. 이후 Receiver가 accept하여 unlock하고 transfer를 완료하거나 reject하거나 expiration까지 기다립니다. Sender도 acceptance 전에 offer를 withdraw하여 locked fund를 되찾을 수 있습니다. [CIP-0078](https://github.com/canton-foundation/cips/blob/main/cip-0078/cip-0078.md) 이후 이 transfer에는 fee가 부과되지 않습니다.

**One-step preapproved transfer.** Receiver가 `TransferPreapproval` contract를 설정했다면 Sender는 Receiver의 acceptance 없이 한 단계로 CC를 transfer할 수 있습니다. Receiver Validator operator가 preapproval의 `provider` Party 역할을 하며 정기 renewal을 처리합니다. Provider가 featured Application Provider이면 transfer가 `AppRewardCoupon`을 생성합니다.

## Wallet API Endpoint

Validator App은 `/v0/wallet/*` path 아래에 Wallet API를 제공합니다. 두 category로 나뉩니다.

**External API**(`wallet-external.yaml`) -- Backward compatibility guarantee가 있는 programmatic wallet interaction용입니다. Subject claim이 Wallet User를 identify하는 JWT가 필요합니다. Endpoint는 다음을 포함합니다.

- `POST /v0/wallet/transfer-offers` -- Transfer offer 생성
- `POST /v0/wallet/transfer-offers/{tracking_id}/status` -- Transfer offer status 확인
- `GET /v0/wallet/transfer-offers` -- Transfer offer 나열
- `POST /v0/wallet/buy-traffic-requests` -- Traffic purchase 요청
- `POST /v0/wallet/buy-traffic-requests/{tracking_id}/status` -- Traffic purchase status 확인

**Internal API**(`wallet-internal.yaml`) -- Wallet UI frontend가 사용하며 backward compatibility guarantee가 없습니다. Endpoint는 다음을 포함합니다.

- `GET /v0/wallet/balance` -- Wallet balance query
- `GET /v0/wallet/amulets` -- UTXO 나열
- `POST /v0/wallet/transactions` -- Transaction history
- `POST /v0/wallet/transfer-offers/accept` -- Transfer offer accept
- `POST /v0/wallet/transfer-offers/reject` -- Transfer offer reject
- `POST /v0/wallet/transfer-offers/withdraw` -- Transfer offer withdraw
- `GET /v0/wallet/user-status` -- User onboarding과 wallet status

전체 OpenAPI specification은 [wallet-external.yaml](https://raw.githubusercontent.com/canton-network/splice/refs/heads/main/apps/wallet/src/main/openapi/wallet-external.yaml)과 [wallet-internal.yaml](https://raw.githubusercontent.com/canton-network/splice/refs/heads/main/apps/wallet/src/main/openapi/wallet-internal.yaml)을 참고하세요.

## UTXO Management

Canton Coin은 Splice의 underlying Amulet contract structure에서 상속된 UTXO model을 사용합니다. Ledger의 각 active `Holding` contract는 특정 CC amount를 가진 단일 UTXO를 나타냅니다. Account balance model과 달리 Party total balance는 모든 개별 Holding UTXO의 합계입니다. Active Holding contract는 Hosting Validator의 storage와 compute를 소비하고 transfer의 각 UTXO input은 추가 Traffic cost를 발생시키므로 Wallet Provider에 UTXO management가 중요합니다.

Canton Coin은 transfer당 input contract를 100개로 제한하며 initial amount가 누적 Holding fee보다 작은 dust UTXO를 expire합니다. Wallet Provider는 사용자당 평균 UTXO를 약 10개 이하로 유지하는 것을 목표로 해야 합니다.

**MergeDelegation contract**를 통해 Wallet Provider가 User를 대신해 작은 Holding UTXO를 merge할 수 있습니다. Workflow는 다음과 같습니다.

1. User가 onboarding 중 `MergeDelegationProposal` creation에 signing합니다.
2. Wallet Provider가 proposal을 accept하여 active `MergeDelegation`을 생성합니다.
3. Background process가 UTXO를 10개보다 많이 가진 User를 identify하고 Registry API를 통해 merge operation을 구성한 뒤 `BatchMergeUtility_MergeHoldings` Choice를 사용하여 약 100개씩 batch로 실행합니다.

MergeDelegation contract를 통해 Wallet Provider는 airdrop campaign과 Holding auto-merge를 하나의 batched call로 결합할 수도 있습니다. Featured Wallet Provider는 merge 수행에 대한 featured app reward를 받습니다.

## External Party Wallet 지원

Validator는 Transaction signing key를 Participant Node 외부에 보유하는 External Party의 CC를 관리하기 위한 API를 제공합니다. External Signing workflow는 Transaction을 Participant에서 prepare하고 external에서 signing한 뒤 Participant로 다시 submit하는 Canton interactive submission 기능을 사용합니다.

External Party의 high-level flow는 다음과 같습니다.

1. `/v0/admin/external-party/topology/*`로 External Party Topology 설정
2. `/v0/admin/external-party/setup-proposal`로 `TransferPreapproval`을 생성하여 CC send/receive 활성화
3. `/v0/admin/external-party/transfer-preapproval/*`로 CC 전송
4. `GET /v0/admin/external-party/balance`로 balance query

각 transfer에서 caller는 Transaction을 prepare하여 hash를 얻고 External Party private key로 hash에 signing한 뒤 signed Transaction을 Participant에 다시 submit해야 합니다. 전체 endpoint 목록은 [validator-internal.yaml](https://raw.githubusercontent.com/canton-network/splice/refs/heads/main/apps/validator/src/main/openapi/validator-internal.yaml) OpenAPI spec을 참고하세요.

TypeScript Wallet SDK를 사용한 custom wallet integration 구축은 [Wallet SDK 문서](/sdks-tools/sdks/wallet-sdk/quickstart)를 참고하세요.
