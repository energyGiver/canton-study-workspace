Wallet Gateway는 Wallet Gateway의 identity, request 제공 방식, data 저장 위치, 시작 시 사용할 Network 및 identity provider를 정의하는 단일 JSON configuration file을 읽습니다. 이 가이드에서는 file 구조와 `kernel`, `server`, `store` section을 설명합니다. Network 및 authentication은 [Network 및 identity provider](/integrations/wallet-gateway/operate/networks-and-identity)를 참조하세요. 전체 field reference는 [Configuration reference](/integrations/wallet-gateway/reference/configuration-reference)를 참조하세요.

## 시작점 생성

편집할 수 있는 example configuration을 작성합니다.

```bash
wallet-gateway --config-example > config.json
```

전체 JSON Schema를 확인하려면 다음을 실행하세요. Validation 및 IDE autocompletion에 유용합니다.

```bash
wallet-gateway --config-schema
```

## File 구조

Configuration file에는 5개의 top-level section이 있습니다.

| Section | 필수 | 목적 |
| --- | --- | --- |
| `kernel` | yes | dApp에 제공되는 이 Wallet Gateway instance의 identity입니다. |
| `server` | yes | Network binding, port, API path 및 admin user입니다. |
| `store` | yes | Session, wallet, network, IDP 및 Transaction을 위한 database 연결입니다. |
| `bootstrap` | yes | 최초 실행 시 seed되는 Network 및 identity provider입니다. |
| `signingStore` | no | Internal signing 사용 시 key를 위한 secondary database입니다. |

Local setup을 위한 최소 configuration은 다음과 같습니다.

```json
{
    "kernel": {
        "id": "remote-da",
        "clientType": "remote"
    },
    "server": {
        "port": 3030,
        "dappPath": "/api/v0/dapp",
        "userPath": "/api/v0/user",
        "allowedOrigins": ["http://localhost:8080"],
        "admin": "operator"
    },
    "store": {
        "connection": {
            "type": "sqlite",
            "database": "store.sqlite"
        }
    },
    "bootstrap": {
        "idps": [],
        "networks": []
    }
}
```

[Network 및 identity provider](/integrations/wallet-gateway/operate/networks-and-identity)에 따라 `bootstrap.idps`와 `bootstrap.networks`를 입력하세요.

## Kernel

`kernel` section은 dApp에 이 Wallet Gateway instance를 식별합니다.

- `id`(필수): 안정적이고 고유한 identifier입니다. 예: `"my-gateway-prod"`.
- `clientType`(필수): Remote Wallet Gateway에는 `"remote"`를 사용합니다.
- `publicUrl`(선택): Client redirect에 사용하는 base URL입니다. 생략하면 server host 및 port에서 파생됩니다. Reverse proxy 또는 load balancer 뒤에서 실행할 때 설정하세요.

```json
{
    "kernel": {
        "id": "my-production-gateway",
        "clientType": "remote",
        "publicUrl": "https://wallet.example.com"
    }
}
```

## Server

`server` section은 binding, port 및 API path를 구성합니다.

- `port`(선택, 기본값 `3030`): Server가 bind하는 port입니다. Discovery flow에서 popup URL을 생성할 때도 사용합니다.
- `dappPath`(선택, 기본값 `/api/v0/dapp`): dApp이 연결하는 path입니다.
- `userPath`(선택, 기본값 `/api/v0/user`): User UI 및 User API가 사용하는 path입니다.
- `allowedOrigins`(선택, 기본값 `["*"]`): CORS에서 허용할 origin입니다. Production에서는 `"*"` 대신 정확한 origin을 나열하세요.
- `requestSizeLimit`(선택, 기본값 `"1mb"`): 최대 request body size입니다.
- `requestRateLimit`(선택, 기본값 `10000`): IP별 분당 최대 request 수입니다. Health endpoint는 제외됩니다.
- `admin`(선택): Admin privilege가 부여되는 user ID(JWT `sub` claim)입니다. 이 권한으로 runtime에 Network 및 identity provider를 관리할 수 있습니다. 생략하면 Network 및 IDP 관리는 bootstrap configuration으로 제한됩니다.

```json
{
    "server": {
        "port": 3030,
        "dappPath": "/api/v0/dapp",
        "userPath": "/api/v0/user",
        "allowedOrigins": ["https://my-dapp.example.com"],
        "requestSizeLimit": "10mb",
        "requestRateLimit": 10000,
        "admin": "operator"
    }
}
```

### Signing worker

Automation이 external custody provider를 통해 signing할 때 `server.signingWorker`는 provider가 승인한 후 Transaction을 완료하는 background worker를 control합니다.

```json
{
    "server": {
        "signingWorker": {
            "pollInterval": 5000
        }
    }
}
```

- `signingWorker.pollInterval`(선택, 기본값 `5000` ms): Transaction이 `pending` 상태인 동안 worker가 external signer(Fireblocks, Blockdaemon, DFNS)를 polling하는 주기입니다. [Service account automation](/integrations/wallet-gateway/automation/service-account-automations)을 참조하세요.

## Store

`store` connection은 Wallet Gateway가 session, wallet configuration, Network, identity provider 및 진행 중인 Transaction을 저장할 위치를 결정합니다. 다음 세 backend를 사용할 수 있습니다.

| Backend | 용도 | Persistence |
| --- | --- | --- |
| `memory` | 빠른 test | Restart 시 사라집니다. |
| `sqlite` | Local development | File에 유지됩니다. |
| `postgres` | Production 및 test | 신뢰성이 높고 확장 및 backup에 적합합니다. |

```json
{
    "store": {
        "connection": {
            "type": "postgres",
            "host": "db.example.com",
            "port": 5432,
            "user": "wallet_gateway",
            "password": "secure-password",
            "database": "wallet_gateway_db"
        }
    }
}
```

<Warning>
Docker 또는 Kubernetes에서 `memory` store를 사용하면 container 또는 pod가 다시 생성될 때 모든 data가 사라집니다. `sqlite`는 database file이 persistent volume에 있을 때만 유지됩니다. Production에는 `postgres`를 사용하세요. Backup 지침은 [Configuration reference](/integrations/wallet-gateway/reference/configuration-reference)를 참조하세요.
</Warning>

TLS를 사용하는 PostgreSQL의 경우 connection에 `ssl` block을 추가합니다. [TLS/SSL을 사용하는 PostgreSQL](/integrations/wallet-gateway/reference/configuration-reference#postgresql-over-tls-ssl)을 참조하세요.

## Signing store

선택 사항인 `signingStore`는 Wallet Gateway가 자체적으로 Transaction을 signing할 때만 사용하는 secondary database입니다(internal signing provider). `store`와 동일한 connection option을 사용합니다. Participant Node 또는 external custody provider를 사용할 때는 완전히 생략하세요.

```json
{
    "signingStore": {
        "connection": {
            "type": "sqlite",
            "database": "signingStore.sqlite"
        }
    }
}
```

<Warning>
Internal signing provider는 private key를 signing store database에 저장합니다. 가치 있는 asset을 다루는 production system에서는 사용하지 마세요. [Signing provider](/integrations/wallet-gateway/operate/signing-providers)를 참조하세요.
</Warning>
