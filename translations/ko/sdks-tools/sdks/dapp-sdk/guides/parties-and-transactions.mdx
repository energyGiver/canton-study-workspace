Wallet이 연결되면 dApp은 인증된 session을 통해 User의 Canton Party를 읽고 message에 서명하며 transaction을 제출하고 Ledger를 query할 수 있습니다.

모든 example은 high-level SDK를 사용합니다. 같은 기능의 low-level call은 [Provider API](/sdks-tools/sdks/dapp-sdk/reference/provider-api)를 참조하세요.

## User Party 조회

User는 여러 Canton Party, 즉 Account에 접근할 수 있습니다. 이를 나열하고 User가 Primary로 지정한 Party를 찾습니다.

```typescript
const accounts = await sdk.listAccounts()
const primary = accounts.find((a) => a.primary)
```

## Primary Party 가져오기

Primary Account만 필요하면 직접 읽습니다.

```typescript
const account = await sdk.getPrimaryAccount()
console.log(account.partyId)
```

<Warning>
Primary Party가 바뀌지 않는다고 가정하지 마세요. User는 Wallet에서 이를 변경할 수 있습니다. 무기한 cache하는 대신 아래의 `onAccountsChanged`를 subscribe하고 Primary Party를 다시 읽으세요.
</Warning>

## Account change 처리

```typescript
const handler = (accounts) => {
    const primary = accounts.find((a) => a.primary)
    setActiveParty(primary?.partyId)
}

sdk.onAccountsChanged(handler)
// On unmount: sdk.offAccountsChanged(handler)
```

## Active Network 읽기

```typescript
const network = await sdk.getActiveNetwork()
console.log(network.networkId) // e.g. 'canton:da-mainnet'
```

dApp이 예상하지 않은 Network에서 동작하지 않도록 transaction 제출 전에 Network를 검증하세요.

## Message 서명

Primary Account로 사람이 읽을 수 있는 임의 string에 서명합니다. 서명을 요청하기 전에 User에게 서명할 내용을 보여주세요.

```typescript
const signature = await sdk.signMessage('Sign in to Example dApp')
```

## Transaction 실행

`prepareExecute()`는 전체 lifecycle을 처리합니다. Daml command를 prepare하고 User의 Wallet에서 승인과 signature를 요청한 뒤 transaction을 Ledger에 제출합니다.

```typescript
const account = await sdk.getPrimaryAccount()

await sdk.prepareExecute({
    commands: [
        {
            CreateCommand: {
                templateId: '<your-package>:<Module>:<Template>',
                createArguments: {
                    // template fields
                },
            },
        },
    ],
})
```

<Note>
첫 end-to-end test에서는 built-in `Ping` Template(`#AdminWorkflows:Canton.Internal.Ping:Ping`)로 round-trip이 동작하는지 확인할 수 있습니다. 실제 dApp에서는 자체 Daml Package의 command를 제출하세요.
</Note>

## Transaction tracking

Transaction lifecycle인 `pending` → `signed` → `executed` 또는 `failed`를 추적하려면 `onTxChanged`를 subscribe합니다.

```typescript
sdk.onTxChanged((tx) => {
    if (tx.status === 'executed') {
        console.log('Update ID:', tx.payload.updateId)
    } else if (tx.status === 'failed') {
        // Surface the failure to the user
    }
})
```

## Ledger query

User session을 통해 Canton JSON Ledger API로 인증된 request를 proxy합니다.

```typescript
const response = await sdk.ledgerApi({
    requestMethod: 'GET',
    resource: '/v2/version',
})

console.log(JSON.parse(response.response))
```

이를 사용하면 별도의 인증된 Ledger API client를 구축하지 않고 Contract, event, version 같은 Ledger data를 읽을 수 있습니다.
