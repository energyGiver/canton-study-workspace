Java binding은 compile된 Daml Package에서 type-safe class를 생성합니다. 이 class를 사용하면 gRPC message나 JSON payload를 직접 구성하지 않고 Java에서 Contract 생성, Choice exercise, Ledger event 처리를 수행할 수 있습니다.

## Code Generation

Compile된 DAR file에서 Java binding을 생성합니다.

<DamlSdksToolsCliToolsDpmL76 />

Daml Module별로 구성된 Java source file이 생성됩니다. 각 Daml Template은 Java class가 되고 각 Choice는 typed field를 가진 nested class가 됩니다.

## Generated Class 구조

Daml Template이 다음과 같다면,

<DamlSdksToolsLanguageBindingsJavaL22 />

Code generator는 다음을 생성합니다.

- **`License` class** -- `provider`, `user`, `description`, `expiresAt` field를 가진 Template payload를 나타냅니다.
- **`License.ContractId` class** -- `License` instance의 typed Contract identifier입니다.
- **`License.Renew` class** -- `newExpiry` field를 가진 `Renew` Choice argument를 나타냅니다.
- **Serialization method** -- Java object와 Ledger API value representation 사이를 변환하는 `toValue()`와 `fromValue()`입니다.

## gRPC Client setup

Generated class는 gRPC Ledger API client와 함께 동작합니다. Validator에 다음처럼 연결합니다.

```java
ManagedChannel channel = ManagedChannelBuilder
    .forAddress("localhost", 2901)
    .usePlaintext()  // Use TLS in production
    .build();

CommandServiceGrpc.CommandServiceFutureStub commandService =
    CommandServiceGrpc.newFutureStub(channel);
```

### Command 제출

Generated class로 Contract를 생성합니다.

```java
License license = new License(
    providerParty,
    userParty,
    "Premium License",
    Instant.parse("2025-12-31T00:00:00Z")
);

// Submit as a create command via the Ledger API
```

Choice를 exercise합니다.

```java
License.Renew renewArg = new License.Renew(
    Instant.parse("2026-12-31T00:00:00Z")
);

// Submit as an exercise command with the contract ID and choice argument
```

### Event 처리

Ledger API stream에서 transaction event를 읽을 때 `fromValue()`로 Contract payload를 deserialize합니다.

```java
CreatedEvent event = ...;
License license = License.fromValue(event.getArguments());
```

## Maven/Gradle dependency

Generated code를 build에 추가합니다. [cn-quickstart](https://github.com/digital-asset/cn-quickstart) project에서는 Gradle이 build process의 일부로 code generation과 compilation을 처리합니다.

Gradle project에는 generated source directory를 추가합니다.

```kotlin
sourceSets {
    main {
        java {
            srcDir("generated-java")
        }
    }
}
```

Maven에서는 `pom.xml`에 generated directory를 source folder로 추가합니다.

```xml
<build>
  <plugins>
    <plugin>
      <groupId>org.codehaus.mojo</groupId>
      <artifactId>build-helper-maven-plugin</artifactId>
      <executions>
        <execution>
          <id>add-source</id>
          <phase>generate-sources</phase>
          <goals><goal>add-source</goal></goals>
          <configuration>
            <sources>
              <source>generated-java</source>
            </sources>
          </configuration>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
```

Daml Java binding library도 dependency로 필요합니다. 현재 Maven coordinate와 version은 [Daml SDK GitHub release](https://github.com/digital-asset/daml/releases)를 참조하세요.

# Java용 Daml Codegen

Java용 Daml Codegen인 `dpm codegen-java`를 사용해 Daml Archive `.dar` file에 정의된 모든 Daml data type을 나타내는 Java class를 생성합니다. 이 class는 `com.daml.ledger.api.v2.CreateCommand`와 `com.daml.ledger.api.v2.ExerciseCommand`처럼 gRPC Ledger API용 Java gRPC binding이 요구하는 type 구성을 단순화합니다. 또한 JSON decoding utility를 제공해 JSON Ledger API 사용 시 JSON 처리를 쉽게 합니다.

Generated class 사용 방법은 Java에서 Contract와 transaction을 다루는 방법을 참조하세요. Codegen setup과 실행 방법은 아래 section을 참조하세요.

## Install

DPM을 설치하면 Java용 Daml Codegen이 설치됩니다.

## Configure

Daml Codegen을 설정하려면 다음 두 방법 중 하나를 선택합니다.

- **Command line configuration**: 모든 설정을 command line에서 직접 지정합니다.
- **Project file configuration**: 모든 설정을 `daml.yaml` file에 정의합니다.

### Command line configuration

Java용 Daml Codegen의 모든 command line option을 보려면 terminal에서 `dpm codegen-java --help`를 실행합니다.

``` none
<DAR-file[=package-prefix]>...
                         DAR file to use as input of the codegen with an optional, but recommend, package prefix for the generated sources.
-o, --output-directory <value>
                         Output directory for the generated sources
-d, --decoderClass <value>
                         Fully Qualified Class Name of the optional Decoder utility
-V, --verbosity <value>  Verbosity between 0 (only show errors) and 4 (show all messages) -- defaults to 0
-r, --root <value>       Regular expression for fully-qualified names of templates to generate -- defaults to .*
--help                   This help text
```

### Project file configuration

위 설정을 Daml project file `daml.yaml`의 `codegen` element에 지정합니다.

다음은 example입니다.

    sdk-version: 3.4.9
    name: quickstart
    source: daml
    init-script: Main:initialize
    parties:
      - Alice
      - Bob
      - USD_Bank
      - EUR_Bank
    version: 0.0.1
    exposed-modules:
      - Main
    dependencies:
      - daml-prim
      - daml-stdlib
    codegen:
      java:
        package-prefix: com.daml.quickstart.iou
        output-directory: java-codegen/src/main/java
        verbosity: 2

## Operate

Project file configuration으로 Daml Codegen을 실행합니다.

    $ dpm codegen-java

또는 command line configuration으로 실행합니다.

    $ dpm codegen-java ./.daml/dist/quickstart-0.0.1.dar=com.daml.quickstart.iou --output-directory=java-codegen/src/main/java --verbosity=2

#### Escaping rule

Java keyword와의 충돌을 피하기 위해 Daml Codegen은 다음 Daml identifier에 escaping rule을 적용합니다.

- 이미 mapping된 built-in type을 제외한 type name
- Constructor name
- Type parameter
- Module name
- Field name

이 identifier가 [Java reserved keyword](https://docs.oracle.com/javase/specs/jls/se12/html/jls-3.html#jls-3.9)와 일치하면 Daml Codegen은 name 뒤에 dollar sign `$`를 붙입니다. 예를 들어 `import` field는 Java에서 `import$` field로 생성됩니다.

#### Generated class

Daml의 모든 User-defined data type인 Template, Record, Variant는 이 section의 설명처럼 하나 이상의 Java class로 표현됩니다.

Generated class의 Java Package는 Daml Module name을 lowercase로 변환한 값입니다.


##### Template

Daml Codegen은 Daml Template에 대해 다음 class를 생성합니다.

> **TemplateName**
> Contract data 또는 Template field를 나타냅니다.
>
> **TemplateName.ContractId**
> 해당 Template의 Contract ID가 다른 Template이나 Record에서 사용될 때 사용됩니다. 예를 들면 `data Foo = Foo (ContractId Bar)`입니다. 이 class는 Java Binding으로 Ledger에 보낼 수 있는 각 Choice의 `ExerciseCommand`를 생성하는 method도 제공합니다.
>
> **TemplateName.Contract**
> Ledger의 실제 Contract를 나타냅니다. `TemplateName.ContractId` type의 Contract ID field와 `TemplateName` type의 Template data field를 포함합니다. Static method `TemplateName.Contract.fromCreatedEvent`를 사용해 [CreatedEvent](/reference/java/com-daml-ledger-javaapi-data/createdevent)를 `TemplateName.Contract` instance로 deserialize할 수 있습니다.
>
<DamlSdksToolsLanguageBindingsJavaL300 />

구체적으로 codegen은 Java class 여섯 개와 Interface 하나를 정의하는 file을 생성합니다.

1.  `Bar`
2.  `Bar.ContractId`
3.  `Bar.Contract`
4.  `Bar.CreateAnd`
5.  `Bar.JsonDecoder$`
6.  `Bar.Exercises`

```java
package com.acme.templates;
```

##### Variant, sum type

##### Parameterized type

<Note>
이 section은 완전성을 위해 포함됩니다. `fromValue`와 `toValue` method는 일반적으로 unbound type parameter가 없는 Template에서 제공됩니다.
</Note>

Daml Codegen은 Daml parameterized type을 표현하기 위해 Java Generic type을 사용합니다.

다음 Daml fragment는 책의 특성을 modeling하는 `BookAttribute` type에서 사용하는 parameterized type `Attribute`를 정의합니다.

<DamlSdksToolsLanguageBindingsJavaL508 />

Daml Codegen은 `Attribute a` data type의 Generic class를 가진 Java file을 생성합니다.

```java
package com.acme.parameterizedtypes;

public class Attribute<a> {
  public final a value;

  public Attribute(a value) { /* ... */  }

  public DamlRecord toValue(Function<a, Value> toValuea) { /* ... */ }

  public static <a> Attribute<a> fromValue(Value value$, Function<Value, a> fromValuea) { /* ... */ }
}
```

###### Generated type value를 Java Binding Value로 변환

Generic type Attribute instance를 Java Binding [Value](/reference/java/com-daml-ledger-javaapi-data/value)로 변환하려면 `toValue` method를 호출합니다. `a` type field를 해당 Java Binding [Value](/reference/java/com-daml-ledger-javaapi-data/value)로 변환하는 function을 `toValuea` argument로 전달합니다. Parameter name은 `toValue`와 type parameter name을 결합하며 이 경우 `a`를 붙인 `toValuea`입니다.

아래 Java fragment는 *method reference* `Int64::new`를 사용해 `java.lang.Long` value를 가진 Attribute를 Java Binding representation으로 변환합니다.

```java
Attribute<Long> pagesAttribute = new Attributes<>(42L);

Value serializedPages = pagesAttribute.toValue(Int64::new);
```

Java Binding [Value](/reference/java/com-daml-ledger-javaapi-data/value) type의 overview는 Daml to Java Type Mapping을 참조하세요.

<Note>
Daml type이 둘 이상의 type parameter를 가진 Record 또는 Variant라면 각 type parameter의 conversion function을 `toValue` method에 전달해야 합니다.
</Note>

###### Java Binding Value에서 generated type value 생성

`toValue` method와 마찬가지로 generated type value를 생성하려면 `fromValue` method를 호출하고 Java Binding [Value](/reference/java/com-daml-ledger-javaapi-data/value) type에서 예상 Java type으로 변환하는 function을 전달합니다.

```java
Attribute<Long> pagesAttribute = Attribute.<Long>fromValue(serializedPages,
    f -> f.asInt64().getOrElseThrow(() -> throw new IllegalArgumentException("Expected Int field").getValue());
```

Java Binding type을 해당 Java type으로 변환하는 method는 Java Binding [Value](/reference/java/com-daml-ledger-javaapi-data/value) class를 참조하세요.

###### 노출되지 않은 parameterized type

Parameterized type이 위 `BookAttributes`처럼 *actual* type이 지정된 type에 포함되어 있다면 enclosing type의 conversion method가 필요한 conversion function parameter를 자동으로 제공합니다.

###### Optional value 변환

Java `Optional` 변환에는 두 step이 필요합니다. `DamlOptional::of` function에 전달하기 전에 내부 value를 변환하도록 `Optional`을 mapping해야 합니다.

```java
Attribute<Optional<Long>> idAttribute = new Attribute<List<Long>>(Optional.of(42));

val serializedId = DamlOptional.of(idAttribute.map(Int64::new));
```

[DamlOptional](/reference/java/com-daml-ledger-javaapi-data/damloptional)을 Java `Optional`로 다시 변환하려면 container method `toOptional`을 사용해야 합니다. 이 method는 container에 포함될 수 있는 value를 다시 변환하는 function을 받습니다.

```java
Attribute<Optional<Long>> idAttribute2 =
  serializedId.toOptional(v -> v.asInt64().orElseThrow(() -> new IllegalArgumentException("Expected Int64 element")));
```

###### Collection value 변환

[DamlCollectors](/reference/java/com-daml-ledger-javaapi-data/damlcollectors)는 `List`와 `Map` 같은 Java collection container를 한 번에 DamlValue로 변환하는 Collector를 제공합니다. 이 Collector의 builder에는 container element를 변환하는 function이 필요합니다.

```java
Attribute<List<String>> authorsAttribute =
    new Attribute<List<String>>(Arrays.asList("Homer", "Ovid", "Vergil"));

Value serializedAuthors =
    authorsAttribute.toValue(f -> f.stream().collect(DamlCollector.toList(Text::new));
```

Daml container를 Java container로 다시 변환하려면 container method `toList` 또는 `toMap`을 사용해야 합니다. 이 method는 container entry를 다시 변환하는 function을 받습니다.

```java
Attribute<List<String>> authorsAttribute2 =
    Attribute.<List<String>>fromValue(
        serializedAuthors,
        f0 -> f0.asList().orElseThrow(() -> new IllegalArgumentException("Expected DamlList field"))
```
