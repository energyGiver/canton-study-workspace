Sandbox는 local machine에서 실행되는 single-Participant Canton Node입니다. Docker/full Network overhead 없이 빠른 개발 cycle을 위해 `dpm sandbox`로 시작합니다.

## Sandbox 시작

<DamlDocsSdksToolsDevelopmentToolsSandboxL10 />

In-memory Ledger를 가진 Canton Participant Node가 시작됩니다. Ledger API는 default로 `localhost:6865`에서 제공됩니다. Process는 foreground에서 실행되며 Ctrl+C로 중지합니다.

Sandbox는 project `daml.yaml`의 SDK version을 사용하므로 먼저 `dpm install`을 실행하세요.

## Sandbox 제공 항목

- Local Synchronizer, 즉 Sequencer/Mediator에 연결된 단일 Participant
- Command 제출/transaction streaming용 Ledger API, gRPC endpoint
- HTTP 기반 접근용 JSON API endpoint
- Party allocation/DAR upload용 Admin API
- Sandbox 중지 시 state가 사라지는 in-memory storage

Sandbox에는 Wallet service나 Canton Coin이 없습니다. 해당 기능에는 [LocalNet](/sdks-tools/development-tools/localnet)을 사용하세요.

## 일반적인 개발 workflow

### Contract upload/test

Daml code를 compile한 후 실행 중인 Sandbox에 DAR를 upload해 상호작용합니다.

<DamlDocsSdksToolsDevelopmentToolsSandboxL34 />

### Backend 연결

Java/TypeScript backend를 Sandbox Ledger API endpoint에 연결합니다. Sandbox는 production Validator와 같은 gRPC/JSON API interface를 지원하므로 backend code를 변경할 필요가 없습니다.

```
# Ledger API (gRPC): localhost:6865
# JSON API: available on a separate port (check sandbox output)
```

### Party allocate

Admin API 또는 Canton Console로 Test Party를 생성합니다.

<DamlDocsSdksToolsDevelopmentToolsSandboxL55 />

## Sandbox/LocalNet 선택

| Scenario | Sandbox | LocalNet |
|----------|---------|----------|
| Ledger API로 Contract logic test | Yes | Yes |
| Codegen serialization test | Yes | Yes |
| Multi-Validator workflow | No | Yes |
| Canton Coin/payment | No | Yes |
| Wallet integration | No | Yes |
| Splice API interaction | No | Yes |
| Docker 없는 빠른 iteration | Yes | No |

**일반 원칙**: Contract 개발 중 빠른 feedback과 single-Participant integration testing에는 Sandbox를 사용합니다. 여러 Validator, payment, Splice service가 필요하면 LocalNet으로 전환합니다.

## Sandbox/Daml Script 선택

Daml Script인 `dpm test`와 Sandbox는 서로 다른 testing 요구사항을 처리합니다.

- **Daml Script**는 Ledger 없이 in-process로 test scenario를 실행합니다. Contract logic, authorization rule, multi-Party workflow를 test하는 가장 빠른 방법이며 Daml model unit test에 사용합니다.

- **Sandbox**는 실제 Canton Node를 실행합니다. Codegen-generated type의 올바른 serialization, backend connection/authentication, JSON API request result 등 application과 Ledger API의 integration을 test할 때 사용합니다.

## Sandbox 중지

Sandbox가 실행 중인 terminal에서 Ctrl+C를 누릅니다. In-memory storage를 사용하므로 shutdown 시 모든 data가 사라집니다. 각 test run이 clean Ledger에서 시작하도록 의도된 동작입니다.

# Sandbox<span id="component-howtos-application-development-daml-sandbox"></span>

Sandbox는 Daml code와 함께 Canton Ledger를 실행하는 program입니다. Ledger는 Synchronizer Node에 연결된 단일 Participant Node라는 가장 단순한 Topology를 사용합니다. Daml code를 실행하는 Canton Ledger가 필요하지만 target Participant Node Topology와 일치할 필요가 없을 때 사용합니다.

## Install

DPM을 설치하면 Sandbox가 설치됩니다.

## Configure

Sandbox는 command line으로 설정합니다.

### Command line configuration

Sandbox의 모든 command line configuration option을 보려면 terminal에서 `dpm sandbox --help`를 실행합니다.

``` none
Usage: dpm sandbox [--port ARG] [--admin-api-port ARG]
                    [--sequencer-public-port ARG] [--sequencer-admin-port ARG]
                    [--mediator-admin-port ARG] [--json-api-port ARG]
                    [--json-api-port-file PATH] [--canton-port-file PATH]
                    [--static-time | --wall-clock-time] [--canton-help]
                    [-c|--config FILE] [--port-file PATH] [--dar PATH] [ARG]

Available options:
  --json-api-port ARG      Port that the HTTP JSON API should listen on, omit to
                           disable it
  --json-api-port-file PATH
                           File to write canton json-api port when ready
  --canton-port-file PATH  File to write canton participant ports when ready
  --canton-help            Display the help of the underlying Canton JAR instead
                           of the Sandbox wrapper. This is only required for
                           advanced options.
  -c,--config FILE         Set configuration file(s). If several configuration
                           files assign values to the same key, the last value
                           is taken.
  --port-file PATH         File to write ledger API port when ready
  --dar PATH               DAR file to upload to sandbox
  --shutdown-stdin-close   Shut down when stdin is closed, disabled by default
  -h,--help                Show this help text
```

인식되지 않은 command-line argument는 기반 Canton JAR에 전달할 argument로 취급됩니다. Terminal에서 `dpm sandbox --canton-help`를 실행해 option을 확인합니다.

### Canton configuration

Sandbox는 내부적으로 default configuration file을 사용해 `sandbox` Participant, `sequencer1` Sequencer, `mediator1` Mediator를 initialize하는 Canton Ledger를 실행합니다.

기반 Canton Ledger를 다음 두 방법 중 하나로 추가 설정합니다.

- `--config filepath`로 default configuration 위에 적용할 추가 configuration file을 지정합니다. 여러 file이 같은 key를 지정하면 마지막 value를 사용합니다.

- `-C key=value`로 특정 key value를 설정합니다. 예를 들어 Sandbox Participant Ledger API port를 override하려면 다음 command를 사용합니다.

  ``` none
  dpm sandbox -C canton.participants.sandbox.ledger-api.port=9999
  ```

### Canton Declarative API

Declarative API로 Canton Ledger에 존재해야 할 DAR, Party, User를 지정할 수 있습니다. Ledger가 DAR upload와 Party/User 생성을 자동으로 처리합니다.

- upload local DARs

``` none
canton.parameters.enable-alpha-state-via-config = yes
canton.parameters.state-refresh-interval = 5s

canton.participants.sandbox.alpha-dynamic.dars = [
  { location = "./my-asset.dar" },
]
```

## 운영

단일 Participant로 Canton을 시작합니다.

``` none
$ dpm sandbox
Starting Canton sandbox.
Listening at port 6865
Canton sandbox is ready.
```

### Sandbox Ledger와 상호작용

Sandbox가 실행되면 다른 Canton instance와 같은 방식으로 상호작용할 수 있습니다. 예를 들어 DAR를 upload하거나 script를 실행합니다.

``` none
$ dpm sandbox --dar <path to DAR>
$ dpm script --ledger-host localhost --port 6865 --dar <path to DAR> --script-name <script name in DAR>
```

`dpm sandbox`는 Canton instance이므로 모든 Canton 사용 문서가 적용됩니다.

### Sandbox Console 연결

`dpm sandbox`로 Sandbox를 local에서 실행한 후 별도 terminal에서 `dpm canton-console` command를 실행해 remote 방식으로 연결할 수 있습니다.

``` none
$ daml canton-console
   _____            _
  / ____|          | |
 | |     __ _ _ __ | |_ ___  _ __
 | |    / _` | '_ \| __/ _ \| '_ \
 | |___| (_| | | | | || (_) | | | |
  \_____\__,_|_| |_|\__\___/|_| |_|

  Welcome to Canton!
  Type `help` to get started. `exit` to leave.

@
```

`exit` command로 session을 종료할 수 있습니다.

#### Built-in 문서

Canton Console에는 built-in 문서가 있습니다. `help` command로 top-level command의 online 문서를 볼 수 있습니다. Console의 여러 object도 `help` method로 접근하는 built-in help를 제공합니다.

예를 들어 다음처럼 `health` object의 help를 요청합니다.

```scala
health.help
```

다음 example처럼 object 내 특정 항목을 더 자세히 볼 수도 있습니다.

```scala
health.help("status")
```

#### Sandbox와 상호작용

Canton Console의 object 중 하나는 Sandbox 자체를 나타냅니다. `sandbox` object로 Sandbox와 상호작용할 수 있습니다. 예를 들어 다음 command로 Sandbox에 load된 DAR를 나열합니다.

```scala
sandbox.dars.list()
```

Console에서는 Party/Package 관리, Sandbox health 확인, pruning operation 등을 수행할 수 있습니다. 추가 기능은 위 built-in 문서와 Canton Console main 문서를 참조하세요.

#### 동작 방식

Canton은 administration/debugging command를 실행할 수 있는 Console을 제공합니다.

`dpm sandbox`로 Sandbox를 실행하면 단일 Synchronizer와 단일 Participant를 가진 Canton in-memory instance가 시작됩니다.

따라서 production 환경과 같은 방식으로 Console을 사용해 실행 중인 Sandbox와 상호작용할 수 있습니다.

Production/staging/testing 환경에서 이 tool을 사용하는 자세한 guide는 Canton Console main 문서를 참조하세요.

### Daml Contract test

Sandbox는 주로 Daml Contract를 isolated 상태로 test하는 첫 단계에 사용됩니다.

### Authorization 활성화 실행

Default로 Sandbox는 request authorization 없이 모든 valid Ledger API request를 accept합니다.

Authorization 문서의 [JWT 기반](https://jwt.io/) access token으로 Sandbox authorization을 활성화하려면 authorization service type과 certificate path를 지정하는 config file을 생성한 후 `dpm sandbox --config auth.conf`로 Sandbox에 제공합니다.

``` none
canton.participants.sandbox.ledger-api.auth-services = [{
    // type can be
    //   jwt-rs-256-crt
    //   jwt-es-256-crt
    //   jwt-es-512-crt
    //   jwt-rs-256-jwks with an additional url
    //   unsafe-jwt-hmac-256 with an additional secret
    type = jwt-rs-256-crt
    certificate = my-certificate.cert
}]
```

`auth-services` setting은 [API configuration 문서](/global-synchronizer/reference/security-configuration#jwt-authorization)에 자세히 설명되어 있습니다.

#### JSON Web Token, JWT 생성

Testing용 access token은 [jwt.io](https://jwt.io/)에서 생성합니다.

#### RSA key 생성

Testing용 RSA key를 생성하려면 다음 command를 사용합니다.

``` none
openssl req -nodes -new -x509 -keyout sandbox.key -out sandbox.crt
```

다음 file이 생성됩니다.

- `sandbox.key`: PEM/DER/PKCS#1 format private key
- `sandbox.crt`: Public key를 포함한 PEM/DER/X.509 Certificate format self-signed certificate

#### EC key 생성

Testing에서 ES256과 함께 사용할 key는 다음 command로 생성합니다.

``` none
openssl req -x509 -nodes -days 3650 -newkey ec:<(openssl ecparam -name prime256v1) -keyout ecdsa256.key -out ecdsa256.crt
```

다음 file이 생성됩니다.

- `ecdsa256.key`: PEM/DER/PKCS#1 format private key
- `ecdsa256.crt`: Public key를 포함한 PEM/DER/X.509 Certificate format self-signed certificate

ES512 key에도 다음 command를 사용할 수 있습니다.

``` none
openssl req -x509 -nodes -days 3650 -newkey ec:<(openssl ecparam -name secp521r1) -keyout ecdsa512.key -out ecdsa512.crt
```

### TLS 활성화 실행

TLS를 활성화하려면 server private key와 certificate chain을 지정해야 합니다. gRPC Ledger API와 Canton Admin API 모두에 TLS가 활성화됩니다. Client authentication을 활성화할 때는 Canton internal process가 사용할 client certificate도 지정해야 합니다. 이 방법은 application identity를 증명하지 않습니다. 즉 request의 `application_id` field가 certificate의 CN, Common Name과 반드시 연관되지는 않습니다. 아래 example config를 참조하세요. 자세한 내용은 Canton TLS configuration 문서를 참조하세요.

``` none
canton.participants.sandbox.ledger-api {
  tls {
    // the certificate to be used by the server
    cert-chain-file = "./tls/ledger-api.crt"
    // private key of the server
    private-key-file = "./tls/ledger-api.pem"
    // trust collection, which means that all client certificates will be verified using the trusted
    // certificates in this store. if omitted, the JVM default trust store is used.
    trust-collection-file = "./tls/root-ca.crt"
    // define whether clients need to authenticate as well (default not)
    client-auth = {
      // none, optional and require are supported
      type = require
      // If clients are required to authenticate as well, we need to provide a client
      // certificate and the key, as Canton has internal processes that need to connect to these
      // APIs. If the server certificate is trusted by the trust-collection, then you can
      // just use the server certificates. Otherwise, you need to create separate ones.
      admin-client {
        cert-chain-file = "./tls/admin-client.crt"
        private-key-file = "./tls/admin-client.pem"
      }
    }
  }
}
```

### Dev Protocol

Canton Dev Protocol을 활성화합니다.

```bash
cat <<EOF
canton.participants.sandbox.parameters.alpha-version-support = true
canton.sequencers.sequencer1.parameters.alpha-version-support = true
canton.parameters {
    non-standard-config = yes
    alpha-version-support = yes
}
EOF > dev-protocol.conf

CANTON_PROTOCOL_VERSION=dev dpm sandbox -c dev-protocol.conf
```

## Troubleshooting

### Address bind failure

Default로 Sandbox는 Canton service용 port 다섯 개를 예약합니다.

- `6865`: Participant Ledger API
- `6866`: Participant Admin API
- `6867`: Sequencer Public API
- `6868`: Sequencer Admin API
- `6869`: Mediator Admin API

`--json-api-port`를 지정하면 해당 port에도 bind합니다.

기존 process가 이 port 중 하나를 이미 사용 중이면 Sandbox가 다음 text를 포함한 error를 emit합니다.

``` none
Failed to bind to address /127.0.0.1:<port number>
```

가장 흔한 원인은 기존 process가 해당 port에서 이미 listen 중이거나 address에 bind할 permission이 없는 경우입니다.

Linux에서 `lsof -n -i` command는 port에서 이미 listen 중인 process를 나열합니다. 기존 Java program이 6865에서 listen 중이라면 `lsof` output은 다음과 같습니다.

``` none
$ lsof -n -i
...
java       707977 username       77u  IPv6 67556378      0t0  TCP 127.0.0.1:6865 (LISTEN)
...
```

기존 process를 종료할 수 없거나 특정 port bind permission이 없다면 다음 top-level option으로 Node port를 다시 설정할 수 있습니다.

- `--port=`로 `6865` bind를 override합니다.
- `--admin-api-port=`로 `6866` bind를 override합니다.
- `--sequencer-public-port=`로 `6867` bind를 override합니다.
- `--sequencer-admin-port=`로 `6868` bind를 override합니다.
- `--mediator-admin-port=`로 `6869` bind를 override합니다.
- `--json-api-port`로 JSON API bind port를 변경합니다.

### SDK가 설치되지 않음

현재 project의 `daml.yaml`이 설치되지 않은 DPM SDK version을 지정하면 다음 error message가 표시될 수 있습니다.

``` none
SDK not installed. Cannot run command without SDK.
```

다음 방법으로 해결합니다.

- Error 안내에 따라 SDK를 설치합니다.
- Project `daml.yaml`의 SDK version을 변경합니다.
- Project 외부 directory로 이동해 system에 이미 설치된 default Daml version을 사용합니다.
