Daml Profiler는 Daml code execution을 profile해 bottleneck과 optimization 기회를 찾는 데 도움을 줍니다.

## Usage

이를 살펴보기 위해 Assistant에 포함된 skeleton project를 사용합니다. 먼저 project를 생성하고 DAR를 build합니다.

``` sh
dpm new profile-tutorial --template skeleton
cd profile-tutorial
dpm build
```

다음으로 특별한 `profile-dir` option을 사용해 DAR를 Sandbox에 load합니다. Sandbox는 평소처럼 동작하지만 모든 profile result를 해당 directory에 기록합니다. 먼저 Sandbox의 `profile-dir`을 설정하는 configuration file을 생성합니다.

``` none
canton.participants.sandbox.features.profile-dir = profile-results
```

그 다음 다음 command를 실행합니다.

``` sh
dpm sandbox --dar .daml/dist/profile-tutorial-0.0.1.dar -c profile.conf
```

실제 profile result를 생성하려면 transaction을 만들어야 합니다. 이 tutorial에서는 skeleton project에 포함된 Daml Script를 사용합니다.

``` sh
dpm script --dar .daml/dist/profile-tutorial-0.0.1.dar --ledger-host localhost --ledger-port 6865 --script-name Main:setup
```

`profile-results` directory에는 script가 생성한 transaction마다 JSON file 하나가 있습니다. File name은 `$timestamp-$command.json` 형식입니다. `$timestamp`는 transaction submission time이고 `$command`는 transaction을 만든 command의 human-readable description입니다. Multi-command submission에서는 첫 command만 file name에 포함됩니다.

``` sh
$ ls profile-results
2021-03-17T12:32:16.846404Z-create:Asset.json
2021-03-17T12:32:17.361596Z-exercise:Asset:Give.json
2021-03-17T12:32:17.623537Z-exercise:Asset:Give.json
```

이 시점에 Sandbox를 중지할 수 있습니다.

Profile result는 [speedscope](https://github.com/jlfwong/speedscope)로 볼 수 있습니다. 가장 간단한 방법은 [web version](https://www.speedscope.app/)을 사용하는 것이며 [local 설치](https://github.com/jlfwong/speedscope#command-line-usage)도 가능합니다.

위의 첫 exercise profile인 `2021-03-17T12:32:17.361596Z-exercise:Asset:Give.json`을 엽니다.

> <img src="/images/docs_website/speedscope.png" className="align-center" style={{width: "100.0%"}} alt="Speedscope results for the first exercise profile. The first activity is just after the 4.00 ms mark." />

Profile root에 exercise가 표시됩니다. 그 아래에는 Signatory, Observer, Controller를 계산하는 expression이 있고 마지막에 Contract create가 표시됩니다. 이 단순한 example에서는 추가 optimization 대상이 뚜렷하지 않습니다.

Speedscope는 profile에 따라 유용한 다른 view도 제공합니다. 자세한 내용은 [문서](https://github.com/jlfwong/speedscope#views)를 참조하세요.

## 주의사항

1.  현재 Profiler는 database에서 Contract를 가져오는 시간처럼 pure interpretation 외부에서 소비된 시간을 고려하지 않습니다.
2.  Profiler는 Daml-LF를 대상으로 동작합니다. 따라서 Profiler의 identifier는 Compiler가 사용하는 autogenerated identifier를 포함한 Daml-LF expression에 대응합니다. 위 example의 `Main:$csignatory`는 `Asset` Signatory를 계산하는 function name입니다. `dpm damlc inspect`로 Compiler가 생성한 Daml-LF code를 볼 수 있습니다. Identifier 사용 위치를 파악하는 데 유용하지만 Daml-LF code를 쉽게 읽으려면 경험이 필요합니다.

``` sh
dpm damlc inspect .daml/dist/profiler-tutorial-0.0.1.dar
```
