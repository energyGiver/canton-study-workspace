Daml Studio는 Daml 개발용 Visual Studio Code extension입니다. Daml code를 작성할 때 type error, syntax highlighting, 통합 test visualization을 포함한 실시간 feedback을 제공합니다.

## 설치

### dpm으로 설치

Daml SDK를 설정하면 extension이 자동으로 설치됩니다. 아무 Daml project directory에서 다음과 같이 실행합니다.

<DamlSdksToolsCliToolsDpmL90 />

Daml extension이 활성화되고 project가 load된 상태로 VS Code가 열립니다. VS Code 1.87 이상이 필요합니다.

### VS Code Marketplace에서 설치

VS Code Marketplace에서 extension을 직접 설치할 수도 있습니다.

1. VS Code를 엽니다.
2. Extensions panel로 이동합니다. Ctrl+Shift+X 또는 Cmd+Shift+X를 사용합니다.
3. "Daml"을 검색합니다.
4. Digital Asset Daml extension을 설치합니다.

직접 설치한 뒤에는 extension이 compiler를 찾을 수 있도록 Daml SDK가 `PATH`에 있는지 확인합니다.

## 기능

### Syntax highlighting

Daml file인 `.daml`에는 keyword, type, Template definition, Choice, expression에 대한 syntax highlighting이 적용됩니다. Color scheme은 VS Code의 활성 theme을 따릅니다.

### Type checking 및 inline error

입력하는 동안 extension이 background에서 Daml compiler를 실행합니다. Type error, 누락된 import, authorization issue는 editor에 빨간 물결 밑줄로 나타납니다. Error 위에 pointer를 올리면 전체 diagnostic message가 표시됩니다.

예를 들어 scope에 없는 Party를 참조하면 다음과 같습니다.

<DamlSdksToolsDevelopmentToolsDamlStudioL43 />

File을 저장하기 전에도 extension이 `missingParty`에 즉시 밑줄을 표시합니다.

### Definition으로 이동

Identifier를 Ctrl+Click, macOS에서는 Cmd+Click하면 해당 definition으로 이동합니다. 같은 Package 안의 여러 file과 standard library function에서 동작합니다.

### Code navigation

- **Find all references** -- Identifier를 right-click하고 "Find All References"를 선택해 모든 사용 위치를 확인합니다.
- **Outline view** -- Sidebar에 현재 file의 Template, Choice, function 구조가 표시됩니다.
- **Breadcrumbs** -- Editor header에 현재 module과 definition path가 표시됩니다.

### Script result

Daml Script function이 있는 file을 열면 각 Script 위에 "Script results" code lens가 나타납니다. 이를 click하면 Script를 실행하고 side panel에서 결과를 볼 수 있습니다.

Result panel에는 두 view가 있습니다.

- **Table view** -- Script 종료 시점의 Active Contract와 각 Contract를 볼 수 있는 Party를 나타내는 column을 표시합니다.
- **Transaction view** -- Sub-transaction을 포함한 모든 transaction을 순서대로 표시해 authorization flow를 이해하는 데 유용합니다.

### Hover 정보

Expression 위에 pointer를 올리면 inferred type이 표시됩니다. 복잡한 expression이나 익숙하지 않은 library function을 다룰 때 유용합니다.

## 문제 해결

### Extension이 load되지 않는 경우

`.daml` file을 열어도 extension이 활성화되지 않으면 다음을 확인합니다.

- Terminal에서 `dpm --version`을 실행해 Daml SDK 설치 여부를 확인합니다.
- `daml` binary가 `PATH`에 있는지 확인합니다.
- Ctrl+Shift+P를 누르고 "Reload Window"를 선택해 VS Code를 reload합니다.
- Output panel의 View > Output에서 dropdown의 "Daml"을 선택해 error message를 확인합니다.

### SDK version 불일치

Extension은 project의 `daml.yaml`에 지정된 SDK version을 사용합니다. Upgrade 또는 project 전환 후 예상하지 못한 error가 나타나면 다음을 확인합니다.

- `dpm install`을 실행해 올바른 SDK version을 download했는지 확인합니다.
- 새 SDK를 인식하도록 VS Code를 닫았다가 다시 엽니다.
- Error가 계속되면 `daml.yaml`의 `sdk-version` field가 설치한 version과 일치하는지 확인합니다.

### 큰 project에서 성능이 느린 경우

Package가 많거나 dependency tree가 큰 project에서는 edit 후 background type checker가 반영하는 데 몇 초가 걸릴 수 있습니다. 지연이 발생하면 다음을 수행합니다.

- Compiler가 cache된 artifact를 재사용하도록 먼저 `dpm build`로 project를 build합니다.
- Extension이 monitor하는 file 수를 줄이기 위해 현재 edit하지 않는 file을 닫습니다.

# Daml Studio

Daml Studio는 Daml용 integrated development environment, IDE입니다. Cross-platform open-source editor로서 [다양한 code editing 기능](https://code.visualstudio.com/docs/editor/editingevolved)을 제공하는 [Visual Studio Code](https://code.visualstudio.com), VS Code의 extension입니다.

## 설치

DPM을 설치해 Daml Studio를 설치하고 [Visual Studio Code](https://code.visualstudio.com) 1.87 이상이 설치되어 있는지 확인합니다.

## 설정

Daml Studio를 연 상태에서 왼쪽의 `Extensions`, Ctrl+Shift+X로 이동합니다. `Daml`을 검색하고 첫 결과의 Cog icon을 click한 다음 settings를 누릅니다. 사용 가능한 option은 Reference에 나열되어 있습니다.

## 사용

Package root, 즉 `daml.yaml`이 있는 directory 또는 project root, 즉 `multi-package.yaml`이 있는 directory로 이동해 `dpm studio`를 실행합니다. Daml extension이 설치되어 실행 중인 Visual Studio Code가 열립니다.

### Definition으로 이동

`F12`를 누르거나 Daml definition을 right-click한 뒤 "go to definition"을 선택해 value/type이 정의된 위치를 확인합니다. Dependency와 data-dependency에도 동작합니다.

[Visual Studio Code Documentation](https://code.visualstudio.com/docs/editor/editingevolved#_go-to-definition).

### Definition 미리 보기

macOS에서 `⌥F12`, Windows/macOS에서 `Ctrl + Shift + F10`을 사용하면 value/type definition을 inline으로 미리 볼 수 있습니다.

[Visual Studio Code Documentation](https://code.visualstudio.com/docs/editor/editingevolved#_peek).

### Hover tooltip

Daml value 위에 pointer를 올리면 source location과 type이 표시됩니다. Daml type 위에서는 source location이 표시됩니다.

[Visual Studio Code Documentation](https://code.visualstudio.com/docs/editor/editingevolved#_hover).

### Diagnostic

`dpm build` 실행 시 발생할 error나 warning이 IDE에 inline으로 표시됩니다. 이 diagnostic은 `build-options`에 지정한 flag의 영향을 받습니다. Daml Yaml Build Options를 참조하세요.

### Daml snippet

Daml IDE는 기본 Template 및 Choice definition 같은 일반적인 Daml pattern을 위한 autocomplete snippet을 제공합니다. `template` 또는 `choice`처럼 definition의 시작 부분을 입력하면 이 snippet이 표시됩니다.

[Creating your own Snippets](https://code.visualstudio.com/docs/editor/userdefinedsnippets)의 안내에 따라 적절한 `daml.json` snippet file을 만들어 자체 snippet을 개발할 수 있습니다.

### Daml Script result

`dpm test`의 일부로 실행되는 top-level definition 위에는 "Script Results" button이 표시됩니다. dpm test를 참조하세요.

이를 click하면 test 실행 결과와 logging 및 Ledger state 정보를 보여주는 side panel이 열립니다.

해당 test의 Daml code를 변경하면 side panel이 실시간으로 update되고, code가 compile되지 않으면 error를 표시합니다. Panel 상단에는 `table` view와 `transaction` view를 전환하는 toggle button이 있습니다.

**Table view**

Table view는 test 중 생성된 모든 Contract, 그 payload, 이를 관찰한 Party를 보여줍니다. 상단에는 archive된 Contract를 표시하는 checkbox와 divulgence 대상 Party의 상세 정보를 표시하는 checkbox도 있습니다. `Show detailed disclosure` checkbox를 사용하면 Party별 Contract 관찰 column에 다음 중 하나가 표시됩니다.

- `S`: 해당 Party가 Contract의 Signatory이므로 Contract를 봅니다.

- `O`: 해당 Party가 Contract의 Observer이므로 Contract를 봅니다.

- `W`: 해당 Party가 Contract 생성을 witness했으므로 Contract를 봅니다. 예를 들어 이를 생성한 `exercise`의 Actor인 경우입니다.

- `D`: 해당 Party에 Contract가 divulge되었으므로 Contract를 봅니다. 예를 들어 이 Contract를 `fetch`한 exercise를 witness한 경우입니다.

**Transaction view**

Transaction view는 생성된 transaction, log, test result를 보여줍니다. Template name, Contract ID, transaction ID 등 이 view의 여러 ID는 각 source로 연결되는 link입니다.

### Multi-package 환경

Daml Studio는 각 `daml.yaml`의 내용을 기준으로 Package마다 별도의 compiler environment를 생성합니다. Daml Studio를 연 directory에 `multi-package.yaml`이 있으면 Jump To Definition이 Package database에서 unpack한 대상이 아니라 이 file에 나열된 Package로 이동할 수 있습니다.

관련 `daml.yaml` file이 변경되거나 dependency DAR가 update될 때마다 Package environment를 reload합니다. 따라서 `dpm build --all`을 실행하면 일반적으로 모든 Package environment가 reload됩니다. 한 Package에서 정의하고 다른 Package에서 사용하는 datatype 변경처럼 dependency를 가로지르는 변경에서는, 후자가 이 변경을 사용하도록 앞 Package의 `.dar` file을 rebuild해야 합니다.

Package environment가 main Package와 같은 SDK version을 사용할 필요는 없습니다. Daml Studio는 관련 Package의 `daml.yaml`에 지정된 version으로 해당 file의 diagnostic을 제공합니다. 설치되지 않은 Daml SDK version을 사용하는 Package를 Daml Studio가 처리하는 방식은 Automatic SDK Installation을 참조하세요.

Parsing할 수 없는 `daml.yaml`이나 누락된 dependency `.dar` 등으로 Daml Studio가 Package environment를 시작하지 못하면 해당 Package의 `daml.yaml` file 상단에 diagnostic을 표시합니다. 이 file을 저장하면 Daml Studio가 다시 시도합니다.

**Root Multi-package SDK**

위에서 설명한 것처럼 각 Package는 자체 environment를 실행하며, 이 environment는 root environment가 관리합니다. 별도로 지정하지 않으면 system에서 가장 최신 SDK를 사용합니다. Project root, 즉 `multi-package.yaml` 옆에 다음 내용만 있는 `daml.yaml` file을 두어 이 version을 override할 수 있습니다.

```yaml
sdk-version: <root-sdk-version>
```

### Dependency definition으로 이동

Daml Studio는 dependency를 unpack해 source code로 이동하는 기능을 지원합니다. 다만 해당 Package의 DAR가 있을 때만 가능합니다. `.dar` file에는 포함된 main Package의 source code가 있지만 함께 bundle된 dependency의 source code는 없습니다. Transitive dependency의 source code로 이동하려면 그 `.dar` path를 main Package의 `daml.yaml` 또는 이 목적만을 위해 존재하는 `multi-package.yaml`의 `dars:` field에 나열할 수 있습니다. 예시는 다음과 같습니다.

```yaml
packages:
- my-package
- libs/my-lib
dars:
- ./dars/my-transitive-dependency-1.0.0.dar
```

### 자동 SDK 설치

설치하지 않은 SDK version을 사용하는 Package의 `.daml` file을 열면 Daml Studio가 해당 SDK version 설치 알림을 표시합니다. 이 알림은 설치 상태와 cancel button을 제공합니다. Daml Studio는 SDK version이 설치되지 않은 Package에 diagnostic을 제공할 수 없습니다.

### Directory environment tool, direnv

`direnv` 같은 tool은 dependency를 설정하고 environment variable interpolation에 사용할 environment variable을 import하는 데 흔히 사용됩니다. Daml Studio에서 이를 사용하려면 다른 extension을 위해 이 환경을 설정하는 VS Code extension이 필요합니다. `.envrc` file이 있어 `direnv`를 사용하는 경우 호환성을 확인한 [Martin Kühl의 direnv extension](https://marketplace.visualstudio.com/items?itemName=mkhl.direnv)을 권장합니다. 다른 direnv extension은 environment 정보를 Daml Studio extension에 올바르게 전달하지 못할 수 있습니다.

Daml extension이 `.envrc` file을 감지하면 IDE에서 다음 message와 함께 이 extension을 권장합니다.

``` 
Found an .envrc file but the recommended direnv VSCode extension is not installed. Daml IDE may fail to start due to missing environment variables.
Would you like to install the recommended direnv extension or attempt to continue without it?
```

VS Code extension marketplace의 해당 extension link도 제공합니다.

## 제한 사항

- Local이 아닌 dependency로 이동할 때 현재는 해당 Package의 build-option과 module-prefix가 유지되지 않습니다. 둘 중 하나가 build에 필요한 dependency로 이동하면 editor가 source code에 error를 표시할 수 있습니다.
- Script Results tab의 일부 link는 Package 경계를 넘어갈 때 올바르게 resolve되지 않을 수 있습니다.
- `daml.yaml`과 source file 사이에 symlink가 있는 Package는 올바른 code intelligence를 제공하지 못할 수 있습니다.

## Upgrade

Daml Studio는 Daml Assistant upgrade와 VS Code marketplace에 새 extension version이 publish될 때 upgrade됩니다.

자세한 내용은 Daml Assistant Upgrade와 Reference의 `--replace` flag를 참조하세요.

## 제거

`dpm studio`가 아닌 Visual Studio Code를 열고 왼쪽의 `Extensions`, Ctrl+Shift+X로 이동합니다. `Daml`을 검색해 첫 결과를 click합니다. `Extension: Daml` page가 열리며 Daml Extension icon 오른쪽에 uninstall button이 있습니다. Daml 자체를 제거하려면 Daml Assistant Decommission을 따르세요.

## 문제 해결

- `Script Results`를 click할 때 `Error loading webview: Error: Could not register service worker ...`가 발생하는 경우

  같은 project에서 VS Code instance가 여러 개 실행 중일 때 발생할 수 있습니다. VS Code를 닫고 모든 process를 종료합니다.

  - Linux/MacOS: `killall code`
  - Windows: Task Manager, Ctrl + Shift + Esc를 열고 모든 VS Code process를 종료합니다.

- Daml Studio가 열린 상태에서 남은 process 또는 build 중 read/write lock error가 발생하는 경우

  > [GitHub Issues page](https://github.com/digital-asset/daml/issues)에 이를 보고한 뒤 Reference에 나온 대로 `Multi-IDE` support를 비활성화하세요.

- 기타 issue

  Daml Studio output log를 읽고 [GitHub Issues page](https://github.com/digital-asset/daml/issues)의 bug report에 포함하면 도움이 될 수 있습니다. 상단 bar에서 View-\>Output을 click하고 새 window 오른쪽 위 dropdown, 현재 `Tasks`로 표시될 수 있음에서 `Daml Language Server`를 선택합니다.

## Reference

### Daml Studio Extension option

Daml Studio Extension에는 다음 option이 있습니다.

- `Autorun All Tests`
  Default: false
  File을 열면 user가 개별 test를 선택할 때까지 기다리지 않고 file의 모든 test를 실행합니다.

- `Extra Arguments`
  `damlc ide`에 전달하는 추가 argument입니다. `--ghc-option -W`로 추가 warning을 활성화하는 데 사용할 수 있습니다.
  이 option은 배포하기가 더 어려우므로 먼저 `daml.yaml`의 `build-options` field 사용을 고려하세요.

- `Log Level`
  Default: Warning
  daml-ide 및 multi-ide의 logging threshold를 설정합니다.

- `Multi Package Ide Support`
  Default: true
  IDE에서 multi-package project support를 활성화합니다.

- `Profile`
  Default: false
  Daml IDE plugin을 profile하며 성능에 영향을 줄 수 있습니다.

- `Telemetry`
  Default: From consent popup
  Daml 사용 data를 Canton Network로 보낼지 제어합니다.

### Daml Studio CLI option

Daml Studio editor를 여는 `dpm studio` CLI command는 다음 flag를 사용합니다.

- `--replace`

  Value: `published`, `always`, `never`

  Default: `published`

  이 flag는 `dpm studio` command가 editor의 VS Code extension을 교체하는 시점을 제어합니다.

  - `published`는 VS Code marketplace에 publish된 가장 최신 Daml Studio VS Code extension version을 항상 사용합니다.
  - `always`는 `daml.yaml`이 선택한 SDK version에 bundle된 extension을 사용합니다. Daml Assistant version management를 참조하세요.
  - `never`는 설치된 extension을 변경하지 않습니다.

  훨씬 오래된 Daml version을 사용해야 한다면 Daml Studio를 올바르게 실행하기 위해 `--replace=always`가 필요할 수 있습니다.
