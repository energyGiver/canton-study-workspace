Canton Validator는 여러 Synchronizer에 동시에 연결할 수 있습니다. 이 방식으로 MainNet이 확장됩니다. Validator는 Network 전체의 interoperability를 위해 Global Synchronizer에 참여하는 동시에, 전용 bandwidth가 필요한 특수 workflow를 위해 하나 이상의 전용 Synchronizer에도 연결됩니다.

## Multi-Synchronizer connection의 작동 방식

각 Synchronizer connection은 독립적입니다. Validator는 각 Synchronizer의 Sequencer에 별도의 communication channel을 유지하며, Contract는 특정 Synchronizer에 assign됩니다. Contract를 생성하면 하나의 Synchronizer에 assign됩니다. 이후 unassignment/reassignment protocol을 사용하여 다른 Synchronizer로 이동할 수 있습니다.

Validator는 각 Contract가 속한 Synchronizer를 추적하고 그에 따라 Transaction을 route합니다. Transaction에 서로 다른 Synchronizer의 Contract가 포함되면 Canton은 Transaction이 실행되는 공통 Synchronizer로 Contract를 reassign합니다. 다만 single-Synchronizer Transaction에 비해 latency가 추가됩니다.

## Contract assignment와 reassignment

Contract가 생성되면 생성 Transaction이 실행되는 Synchronizer에 assign됩니다. 적절한 Synchronizer connection을 통해 Command를 제출하여 이를 제어합니다.

Contract를 다른 Synchronizer로 이동하려면 다음을 실행합니다.

<CantonGlobalSynchronizerExtensionSynchronizersLinkingValidatorMultiSyncL100 />

Unassignment와 reassignment 사이에는 Contract를 잠시 사용할 수 없습니다. Source와 target Synchronizer가 모두 Validator에 연결되어 있어야 하며, Contract의 모든 stakeholder가 target Synchronizer에 연결된 Validator를 보유해야 합니다.

## Contract에 적합한 Synchronizer 선택

Contract를 assign할 위치를 결정할 때 다음 요인을 고려하세요.

- **누가 Contract를 확인해야 하나요?** Contract stakeholder를 host하는 모든 Validator가 Contract의 Synchronizer에 연결되어 있어야 합니다.
- **Transaction 빈도**: 빈도가 높은 bilateral workflow는 capacity를 제어하고 traffic fee를 줄일 수 있는 전용 Synchronizer에서 더 효율적으로 실행됩니다.
- **Settlement 요구 사항**: Contract가 최종적으로 Canton Coin 또는 Global Synchronizer Contract와 상호작용한다면 reassignment 단계를 계획하세요.
- **Privacy 요구 사항**: 전용 Synchronizer의 Contract는 사용자가 제어하는 infrastructure에서만 처리됩니다. Global Synchronizer에서는 Sequencer와 Mediator를 Super Validator가 운영합니다.

## Troubleshooting

**Connection refused 또는 timeout:**
- Sequencer URL이 올바르고 Validator Network에서 접근할 수 있는지 확인하세요.
- TLS certificate가 valid하고 trusted 상태인지 확인하세요.
- Firewall 또는 Network policy가 Sequencer port로 나가는 connection을 허용하는지 확인하세요.

**Connect 후 Synchronizer가 목록에 없음:**
- Validator log에서 connection error를 확인하세요.
- Synchronizer가 initialize되었고 Sequencer가 healthy 상태인지 확인하세요.
- Validator identity가 target Synchronizer에서 authorize되었는지 확인하세요.

**Contract reassignment 실패:**
- Validator가 source와 target Synchronizer에 모두 연결되어 있는지 확인하세요.
- 모든 Contract stakeholder가 target Synchronizer에 연결된 Validator를 보유하는지 확인하세요.
- Contract가 현재 다른 Transaction에서 exercise되고 있지 않은지 확인하세요.

# Synchronizer connection

Participant Node는 해당 Synchronizer의 하나 이상의 Sequencer에 연결하여 Synchronizer에 연결됩니다.

Participant Node는 여러 Synchronizer에 동시에 연결할 수 있습니다. Synchronizer connectivity Command를 통해 Participant Node administrator가 Synchronizer connectivity를 관리할 수 있습니다.

다음 section에서는 Participant Node의 Sequencer connection을 관리하는 방법을 설명합니다.


2.  Sequencer connection을 생성합니다.

3.  Message를 valid한 것으로 간주하기 전에 합의해야 하는 최소 Sequencer 수를 설정하여 Sequencer trust threshold를 구성합니다.

- Default: 1
- Maximum: Connection 수

예를 들어 threshold를 2로 설정합니다.

<ExternalCantonMainDocsOpenTargetSnippetJsonDataParticipantHowtosOperateSynchronizersConnectivity9 />

4.  \[Connection pool에만 해당\] Sequencer liveness margin을 구성합니다. 이는 `sequencerTrustThreshold` 개수에 더하여 message 읽기를 시도할 Sequencer connection 수를 설정합니다.

- Default: 0
- 값이 높을수록 Sequencer 지연 또는 failure에 대한 resilience가 높아지지만, (`sequencerTrustThreshold` + `sequencerLivenessMargin` \> connection 수)이면 추가 이점이 없습니다.

예를 들어 liveness margin을 1로 설정합니다.

<ExternalCantonMainDocsOpenTargetSnippetJsonDataParticipantHowtosOperateSynchronizersConnectivity10 />

5.  Submission request amplification을 구성합니다. Deduplication 대상 submission request를 client가 전송할 시도 횟수를 정의합니다.

- 값이 높을수록 submission request가 system에서 accept될 가능성이 커지지만 Sequencer 부하도 증가합니다.
- Default: `SubmissionRequestAmplification.NoAmplification`

이 예에서는 submission request가 두 Sequencer에 전송되도록 보장하려 합니다. 따라서 amplification factor를 2로, patience를 0초로 설정합니다.
