## CometBFT Helm values

1)  State sync 비활성화

{/* */}

    stateSync:
    -      enable: true
    -      rpcServers: "..."
    +      enable: false

2)  Single SV config에서는 이제 하나의 SV를 bootstrap하므로 자체 key를 입력합니다.

{/* */}

    sv1:
    +    keyAddress: "..."
    +    nodeId: "..."
    +    publicKey: "..."

## Scan Helm values

Value 하나를 추가합니다.

    +    isFirstSv: true

## SV Helm values

1)  joinWithKeyOnboarding 제거

{/* */}

    -    joinWithKeyOnboarding:
    -      sponsorApiUrl: https://sv.sv-2.whatever.global.canton.network.digitalasset.com

2)  Initial Helm values를 추가합니다. 이 number value를 사용하거나 다른 값을 선택할 수 있습니다.

{/* */}

    +    isDevNet: true
    +    onboardingType: found-dso
    +
    +    // see note below about the rest of these:
    +    initialSynchronizerFeesConfig:
    +      baseRateBurstAmount: 400000
    +      baseRateBurstWindowMins: 20
    +      extraTrafficPrice: 16.670000000000002
    +      minTopupAmount: 200000
    +      readVsWriteScalingFactor: 4
    +    onboardingFoundingSvRewardWeightBps: 10000

3)  `sv-values.yaml`에서 `decentralizedSynchronizerUrl` config를 제거합니다. Initial SV 이후에 join하는 Node에만 사용됩니다.

## 고려할 수 있는 다른 Helm values

- TARGET_CLUSTER/TARGET_HOSTNAME을 사용하는 모든 위치에서 자체 Network base domain을 가리키도록 설정합니다.
  - 예를 들어 Network 기반 domain이 hub-scratch.global.canton.network.digitalasset.com이면 다음과 같이 설정합니다.
    - targetCluster = hub-scratch
    - targetHostname = hub-scratch.global.canton.network.digitalasset.com
- walletSweep를 사용하는 경우 Validator도 deploy할 계획이 아니라면 이 scratch environment에서는 아마 사용하지 않을 것입니다.

## 고려할 수 있는 infrastructure level 사항

- Internal VPN 또는 사용자가 제어하는 유사 Network에 cluster를 expose하도록 IP allowlist를 구성합니다. 현 시점에는 public Internet에 expose하지 않는 것이 좋습니다.
- 승인된 SV identity(SV Helm values에 반영됨): 하나의 bootstrapping Node를 deploy하는 경우 이를 `\[\]`로 설정할 수 있습니다.
