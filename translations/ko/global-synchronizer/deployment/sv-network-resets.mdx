<Tab title="DevNet (0.7.1)">

DevNet과 TestNet은 약 3개월마다 reset되며 두 network의 reset이 동시에 일어나지 않도록 시기를 분산합니다. 정확한 시간은 [Global Synchronizer Foundation](https://sync.global/)이 운영하는 `#supervalidator-operations` channel에서 발표합니다.

Reset에는 node의 전체 redeployment가 필요하며 node의 모든 data가 손실됩니다. Reset을 완료할 때까지 node는 작동하지 않습니다. Node redeployment를 시도하기 전에 bootstrapping SV-1이 자체 node redeployment를 완료했다고 발표할 때까지 기다리세요.

Reset을 완료하려면 다음 단계를 수행합니다.

1.  Reset 후에도 보존할 정보를 backup합니다.
    1.  DSO configuration을 backup합니다. YOUR_SCAN_URL을 자체 scan으로 교체합니다. 예: <a href="https://scan.sv-1.dev.global.canton.network.sync.global">https://scan.sv-1.dev.global.canton.network.sync.global</a>

        > curl -sSL --fail-with-body https://YOUR_SCAN_URL/api/scan/v0/dso > backup.json

        Backup을 통해 reset의 일부로 SV weight와 package version이 변경되지 않았는지 확인할 수 있습니다.

    2.  SV UI에서 원하는 amulet price를 기록합니다.

    3.  SV UI에서 진행 중인 모든 vote를 기록합니다. 진행 중인 vote는 reset 과정에서 손실되며 reset 후 수동으로 다시 생성해야 합니다.

    4.  모든 featured app을 기록합니다.

        > curl -sSL --fail-with-body [https://YOUR_SCAN_URL/api/scan/v0/featured-apps](https://YOUR_SCAN_URL/api/scan/v0/featured-apps) \> featured.json

        Featured app right는 reset 과정에서 손실되며 reset 후 수동으로 다시 생성해야 합니다.
2.  이전 node를 decommission합니다.
    1.  모든 Helm chart를 uninstall합니다.
    2.  모든 PVC, Docker volume 및 database를 삭제합니다. Amazon AWS, GCP CloudSQL 등의 database도 포함됩니다.
3.  새 node를 배포합니다.
    1.  Helm chart values에서 serial ID를 0으로 설정합니다. Serial ID는 모든 Helm chart에서 자체 값으로도 나타나고, 예를 들면 다음과 같습니다.

        또한 여러 값의 일부로도 나타납니다. 예:

        >    sequencerPublicUrl: "https://sequencer-SERIAL_ID.sv.YOUR_HOSTNAME"

    2.  `sv-values.yaml`에서 `skipInitialization`을 `false`로 설정합니다.

    3.  `sv-values.yaml`에서 `initialAmuletPrice`를 원하는 price로 설정합니다. 1.b 단계를 참조하세요.

    4.  `cometbft-values.yaml` 및 `info-values.yaml`에서 `chainIdSuffix`를 새 값으로 설정합니다. 일반적으로 network reset 시 1만 증가하지만 합의된 값을 다른 SV operator에게 다시 확인하세요.

    5.  Founding node만 해당: 아래 verification step이 통과하도록 network parameter에 영향을 주는 모든 Helm chart value를 설정합니다.

    6.  모든 Helm chart를 install합니다.

    7.  SV node가 status report를 보낼 때까지 기다립니다.
4.  Network parameter가 보존되었는지 확인합니다.
    1.  1.a 단계를 반복하고 result를 비교하여 reset이 DSO rule을 변경하지 않았는지 확인합니다.

        ```bash
        curl -sSL --fail-with-body https://YOUR_SCAN_URL/api/scan/v0/dso > current_state.json
        ```
        Reset은 SV reward weight를 보존해야 하므로 다음 diff가 비어 있어야 합니다.

        ```bash
        jq '.dso_rules.contract.payload.svs.[] | [.[1].name, .[1].svRewardWeight]' backup.json > weights_backup.json
        jq '.dso_rules.contract.payload.svs.[] | [.[1].name, .[1].svRewardWeight]' current_state.json > weights_current.json
        diff -C2 weights_backup.json weights_current.json
        ```
        Reset은 cryptographic key를 제외한 amulet rule도 보존해야 하므로 다음 diff에는 DSO 및 synchronizer namespace 변경만 표시되어야 합니다.

        ```bash
        jq '.amulet_rules.contract.payload' backup.json > amulet_backup.json
        jq '.amulet_rules.contract.payload' current_state.json > amulet_current.json
        diff amulet_backup.json amulet_current.json
        ```
    2.  SV UI에서 원하는 coin price를 확인하고 reset 전 값과 일치하는지 검증합니다. 1.b 단계를 참조하세요.

    3.  Scan UI에서 current round를 확인하고 예상 값과 일치하는지 검증합니다. Round number는 reward distribution에 영향을 줍니다. 일반적으로 TestNet이 MainNet보다 1주, 약 1008 round 앞서도록 하며 DevNet은 보통 round 0으로 reset합니다.
5.  Reset 과정에서 변경되는 node identity를 backup합니다.
6.  기타 reset 후 action
    1.  Reset 시점에 진행 중이던 vote를 다시 생성합니다. 1.c 단계를 참조하세요.
    2.  Sponsor하는 validator에 onboarding secret을 다시 발급합니다. TestNet에만 해당하며 DevNet에서는 자체 발급할 수 있습니다.
    3.  Validator가 요청하면 featured app vote를 다시 생성합니다. Validator가 sponsor에게 연락하고 sponsor가 vote를 시작해야 합니다. 필요하면 1.d 단계에서 backup한 featured app 목록을 참조하세요.
    4.  Reset 과정에서 party ID가 변경되므로 auto-sweeping configuration을 update합니다.
