## Network

DevNet, TestNet, MainNet이라는 세 network가 있습니다. Validator node 설정에만 관심이 있다면 연습을 위해 DevNet에 node를 설정한 다음 MainNet으로 이동할 수 있습니다. App을 build, test 또는 deploy하려면 DevNet, TestNet 및 MainNet에서 node를 실행하는 것이 좋습니다.

- **DevNet** — DevNet은 모든 node에 개방되어 있지만 validator egress IP를 SV node operator가 유지하는 allowlist에 추가해야 합니다. 3개월마다 reset됩니다. DevNet은 항상 TestNet과 MainNet보다 먼저 새 version으로 upgrade되므로 MainNet에 도달하기 전에 node upgrade와 app에 미치는 영향을 테스트하기 좋습니다.
- **TestNet** — TestNet에 참여하려면 Canton Foundation의 Tokenomics Committee로부터 MainNet 참여 승인을 받아야 합니다. [https://sync.global/validator-request/](https://sync.global/validator-request/)에서 request를 시작할 수 있습니다. DevNet과 마찬가지로 validator egress IP를 allowlist에 추가해야 하며 SV sponsor의 onboarding secret이 필요합니다. TestNet도 3-6개월마다 reset되지만 reset schedule을 분리하여 DevNet과 동시에 reset되지 않도록 합니다. TestNet은 DevNet 이후, MainNet 이전에 새 version으로 upgrade되어 추가 testing layer를 제공합니다. Application provider는 TestNet에서 app의 long-running instance를 유지하는 것이 좋으며, 이를 통해 TestNet에서 composed application을 테스트할 수 있습니다.
- **MainNet** — MainNet은 Tokenomics committee 승인, allowlist의 IP 및 SV sponsor의 onboarding secret 등 TestNet의 모든 요구 사항을 필요로 합니다. MainNet은 reset되지 않으므로 data가 항상 보존되는 유일한 network입니다. MainNet은 DevNet과 TestNet 이후에 새 version으로 upgrade됩니다.

## Onboarding Process 개요

Validator onboarding에는 참여하려는 각 network에 대해 다음 단계가 포함됩니다.

1.  Sponsor SV에 Validator node의 egress IP를 제공합니다. Network당 IP 하나만 제공할 수 있으며, 이 IP는 다른 세 network에 사용하는 IP와 달라야 합니다.

    <Note>
    현재는 SV가 운영하는 VPN을 통해 validator를 연결하여 이를 수행할 수도 있습니다. Local laptop에서 validator를 실행할 때 유용할 수 있습니다. 이 option은 향후 제거될 수 있습니다.
    </Note>

2.  Super validator가 새 IP allowlist를 adopt할 때까지 기다립니다. 일반적으로 2-7일이 걸립니다.

3.  Laptop에서 Canton Coin Scan Web UI에 접근하려면 SV 중 하나가 운영하는 VPN에 연결할 수 있는지도 확인해야 합니다. Laptop에는 일반적으로 static IP address가 없고 Scan web UI는 아직 완전히 public이 아니므로 필요합니다. Web UI browsing에도 validator egress IP를 사용할 수 있다면 필요하지 않습니다.

4.  SV sponsor에게 onboarding secret을 요청합니다. DevNet에서는 API call을 통해 직접 생성할 수 있습니다. 자세한 내용은 Deployment 지침을 참조하세요. TestNet 및 MainNet에서는 SV sponsor가 수동으로 제공해야 합니다. Onboarding secret은 48시간 동안만 유효하고 한 번만 사용할 수 있으며, 직접 생성한 DevNet secret은 1시간 동안만 유효합니다. 만료되면 새 secret을 요청해야 합니다.

5.  Docker Compose 또는 Kubernetes를 사용하여 node를 배포합니다. 두 방식 중에서 선택하는 방법과 각 접근 방식의 reference는 Deployment Option을 참조하세요. Validator에서 SV로 나가는 모든 IP traffic이 SV sponsor에게 제공한 egress IP를 사용하도록 해야 하며 onboarding secret을 제공해야 합니다.

<Tab title="DevNet (0.7.1)">

SV가 각자의 IP allowlist에 사용자를 추가했는지 검증하려면 Scan URL을 query할 수 있습니다. 이 작업은 validator를 배포하려는 것과 동일한 egress IP, 예를 들어 Docker Compose setup을 실행할 VM 또는 Kubernetes cluster 내부에서 실행해야 합니다.

먼저 command를 실행 중인 terminal의 egress IP가 whitelist 등록을 위해 제공한 IP와 실제로 동일한지 다음을 실행하여 확인하세요.

```bash
curl -sSL http://checkip.amazonaws.com
```
IP가 whitelist 등록을 위해 제공한 값과 일치하는지 확인합니다. 일치한다면 다음 command를 실행하여 연결할 수 있는 Scan instance를 확인합니다.

다음 snippet을 사용하려면 [jq](https://jqlang.org/)를 install해야 합니다.

```bash
(set -o pipefail
CURL='curl -fsS -m 5 --connect-timeout 5'
for url in $($CURL https://scan.sv-1.dev.global.canton.network.sync.global/api/scan/v0/scans | jq -r '.scans[].scans[].publicUrl'); do
  echo -n "$url: "
  $CURL "$url"/api/scan/version | jq -r '.version'
done)
```
아래와 같은 output이 표시되어야 하며 각 line은 SV 하나와 해당 version을 나타냅니다. Timeout이 표시되면 해당 SV가 아직 allowlist에 사용자를 추가하지 않은 것입니다. Error가 없다면 모든 SV가 사용자를 추가한 것입니다. URL과 version은 시간이 지나면서 달라지므로 정확히 비교하지 마세요.

```bash
https://scan.sv-2.test.global.canton.network.digitalasset.com: 0.3.6
https://scan.sv.test.global.canton.network.tradeweb.com: 0.3.6
https://scan.sv-1.test.global.canton.network.cumberland.io: 0.3.6
https://scan.sv-1.test.global.canton.network.orb1lp.mpch.io: 0.3.6
https://scan.sv-1.test.global.canton.network.sync.global: 0.3.6
https://scan.sv.test.global.canton.network.sv-nodeops.com: 0.3.6
https://scan.sv-1.test.global.canton.network.mpch.io: 0.3.6
https://scan.sv-2.test.global.canton.network.cumberland.io: 0.3.6
https://scan.sv-1.test.global.canton.network.c7.digital: 0.3.6
https://scan.sv-1.test.global.canton.network.digitalasset.com: 0.3.6
```
Scan connectivity 외에도 validator는 SV의 sequencer endpoint에 연결할 수 있어야 합니다. Synchronizer 연결 관련 문제가 발생하면 다음 snippet을 사용하여 해당 endpoint에 접근할 수 있는지, 즉 SV가 해당 endpoint에서도 IP를 whitelist했는지 확인할 수 있습니다. 다음 snippet을 사용하려면 [jq](https://jqlang.org/)와 [grpcurl](https://github.com/fullstorydev/grpcurl)을 install해야 합니다.

```bash
(set -o pipefail
for url in $(curl -fsS -m 5 --connect-timeout 5 https://scan.sv-1.dev.global.canton.network.sync.global/api/scan/v0/dso-sequencers | jq -r '.domainSequencers[].sequencers[].url | sub("https://"; "")'); do
  echo -n "$url: "
  grpcurl --max-time 10 "$url":443 grpc.health.v1.Health/Check
done)
```
정상 작동하고 IP를 올바르게 whitelist한 sequencer는 `grpcurl` output에서 `"status": "SERVING"`을 반환합니다.

```bash
sequencer-1.sv-2.test.global.canton.network.digitalasset.com: {
  "status": "SERVING"
}
sequencer-1.sv.test.global.canton.network.tradeweb.com: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.cumberland.io: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.orb1lp.mpch.io: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.sync.global: {
  "status": "SERVING"
}
sequencer-1.sv.test.global.canton.network.sv-nodeops.com: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.mpch.io: {
  "status": "SERVING"
}
sequencer-1.sv-2.test.global.canton.network.cumberland.io: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.c7.digital: {
  "status": "SERVING"
}
sequencer-1.sv-1.test.global.canton.network.digitalasset.com: {
  "status": "SERVING"
}
```
두 항목의 기본 configuration은 Scan과 sequencer 각각에서 SV의 최소 2/3에 접근할 수 있어야 합니다. 자체 선택과 책임으로 [validator Helm chart configuration](/global-synchronizer/deployment/validator-kubernetes)에 설명된 단일 trusted Scan 및 sequencer 연결을 구성할 수 있지만 BFT integrity guarantee를 잃게 됩니다.

## 계속 소통하기

다른 validator operator와 소통할 수 있도록 shared Slack channel과 몇 가지 mailing list가 있습니다.

### Slack

### Mailing List

`Canton Foundation`이 제공하는 여러 mailing list에 등록할 수 있습니다. 먼저 [https://groups.io/](https://groups.io/)에서 account를 생성한 다음 [https://lists.sync.global/](https://lists.sync.global/)에 log in합니다. 다음 list를 권장합니다.

- [main](https://lists.sync.global/g/main/messages): Canton Network 전반의 정보
- [cip announce](https://lists.sync.global/g/cip-announce/messages): 새 Canton Improvement Proposal(CIP)
- [tokenomics-announce](https://lists.sync.global/g/tokenomics-announce/messages): Tokenomics committee의 announcement. 새 validator 승인도 포함됩니다.
- [validator-announce](https://lists.sync.global/g/validator-announce/messages): Validator operator를 위한 기타 announcement
