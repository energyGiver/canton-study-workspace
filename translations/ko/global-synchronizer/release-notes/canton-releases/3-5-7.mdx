# Canton 3.5.7 릴리스

Canton 3.5.7이 2026년 7월 1일에 릴리스되었습니다.

## 요약

이 릴리스는 command completion을 가져오는 새로운 Ledger API endpoint를 제공하고 여러 사소한 문제를 수정합니다.

## 새로운 기능

### Command completion service의 새로운 `GetCompletions` endpoint
#### 배경
Command completion service는 항상 단일 user와 비어 있지 않은 party 집합으로 필터링하는 `CompletionStream`만 제공했습니다. 모든 party에 걸쳐 completion을 스트리밍할 방법은 없었습니다.

#### 구체적인 변경 사항
새로운 completion streaming endpoint인 `GetCompletions`(gRPC) 또는 `/commands/command-completions`(JSON API)가 도입되었습니다. 이 endpoint는 기존 `CompletionStream`, `/commands/completions` endpoint보다 유연한 필터링 의미 체계를 제공합니다. `parties`로만 필터링하며 user 필터링은 없습니다.
- 비어 있지 않은 `parties`는 해당 party들로 필터링하며 각 party에 대한 `ReadAs` 또는 `ActAs`가 필요합니다.
- 빈 `parties`는 모든 party의 completion을 반환하며 `ReadAsAnyParty` 또는 `ActAsAnyParty`가 필요합니다.

그 밖의 모든 측면에서는 `CompletionStream`처럼 동작하며, `CompletionStream`은 deprecated됩니다.

#### 영향 및 마이그레이션
이는 기존 기능에 추가되는 변경입니다. `CompletionStream`은 변경되지 않으므로 마이그레이션이 필요하지 않습니다.

### Participant Local Traffic Accounting

참고: 이는 beta 기능입니다.

#### 배경
Participant는 Daml transaction의 confirmation request를 포함하여 synchronizer에 보내는 모든 message의 traffic 비용을 지불해야 합니다.
이 비용은 주로 Ledger API submission에서 발생하며, 현재는 비용을 발생시킨 submitting party에 쉽게 귀속할 수 없습니다.

#### 구체적인 변경 사항
이 릴리스는 Daml transaction 실행을 위해 participant가 submitting party를 대신하여 사용한 traffic을 추적하는 기능을 도입합니다.
각 submitting party에는 account가 암묵적으로 연결되며, submission의 traffic cost가 해당 account에서 차감됩니다.
Account에서 차감되는 비용은 completion response에서 이미 제공되는 비용입니다.

단일 `actAs` party를 가진 submission만 accounting 대상입니다. 여기에는 local party도 포함됩니다.

Traffic accounting 기능이 활성화되면 Ledger API에서 새로운 [service](https://github.com/digital-asset/canton/blob/release-line-3.5/community/traffic-enforcement/api/protobuf/com/digitalasset/canton/tea/v1/traffic_service.proto)를 사용할 수 있으며 다음 작업을 제공합니다.
- 특정 party의 현재 account balance 조회, 해당 party에 대한 ExecuteAs 권한 필요
- Account에 traffic 추가, participant에 대한 Admin 권한 필요

이 기능은 기본적으로 비활성화되어 있으며 `canton.participants.<participant_name>.traffic-enforcement.enabled = true` configuration option을 `true`로 설정하여 활성화할 수 있습니다.
비활성화 상태에서는 `TrafficService`가 Ledger API에 노출되지 않고 accounting이 수행되지 않으며 submission에 enforcement도 적용되지 않습니다.

기능이 활성화되면 accounting은 수행되지만 enforcement는 기본적으로 비활성화되어 있습니다.
Traffic enforcement를 활성화하려면 `canton.participants.<participant_name>.traffic-enforcement.enforce-cost-on-submissions = true`로 설정합니다.
Enforcement가 활성화되면 participant는 submission 시 submitting account에 submission 비용을 지불할 충분한 traffic이 있는지 확인합니다. 충분하지 않으면 submission이 거부됩니다.

Enforcement가 활성화되어 있어도 동일한 submitting party에서 concurrent submission이 이루어지면 account balance가 음수가 될 수 있습니다.

#### 영향 및 마이그레이션
이 변경에는 database migration이 필요합니다. Migration은 추가적인 변경만 수행하지만 기능 활성화 여부와 관계없이 실행됩니다.


### 사소한 개선 사항
- KMS signing 및 decryption operation의 latency metric을 추가했습니다.
- 새로 onboarding된 node가 멈출 수 있던 BFT ordering sequencer crash-recovery 문제를 수정했습니다.
- LSU: sequencer와 successor 사이의 handshake를 개선하여 이제 physical synchronizer ID와 sequencer ID를 검증합니다.
- 이제 JSON Ledger API는 request에 제공된 잘못된 identifier, 예를 들어 `<package>:<moduleName>:<entityName>` 형식을 따르지 않는 template-id를 internal error로 노출하는 대신, 예상 형식을 명시하는 설명적인 `400 Bad Request` error와 함께 거부합니다.
