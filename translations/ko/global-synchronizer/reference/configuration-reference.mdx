이 페이지에서는 Canton Network의 validator 및 Super Validator(SV) operator가 사용할 수 있는 configuration option을 설명합니다. Splice app configuration, Canton participant setting, database setup, authentication, traffic management, pruning 및 observability를 다룹니다.

Application developer configuration(Canton + DPM)은 [AppDev Configuration Reference](/appdev/reference/configuration-reference)를 참조하세요.

## Configuration format

### Helm chart configuration

Helm으로 배포할 때 Helm values file의 `additionalEnvVars` field를 통해 `ADDITIONAL_CONFIG` 값을 전달합니다. 전체 Helm values 집합은 아래 `standalone-validator-values.yaml` section을 참조하세요.

### Custom bootstrap script

Custom bootstrap script는 node startup 시 Canton Console command를 실행합니다. 이 section은 향후 update에서 확장됩니다. Script syntax 및 example은 [Canton Console Scripting](/global-synchronizer/canton-console/scripting) 페이지를 참조하세요.

## Validator node configuration

### 필수 network parameter

Validator가 network(DevNet, TestNet 또는 MainNet)에 연결하려면 다음 값이 필요합니다.

- **MIGRATION_ID** -- Target network의 현재 migration ID입니다. [sync.global/sv-network](https://sync.global/sv-network/)에서 확인하세요.
- **SPONSOR_SV_URL** -- Sponsor SV app의 URL, 예를 들어 CF SV URL입니다.
- **ONBOARDING_SECRET** -- Sponsor SV가 제공한 one-time secret입니다. Secret은 48시간 후 만료됩니다.
- **TRUSTED_SCAN_URL** -- 신뢰하는 SV의 Scan URL이며, BFT read를 위한 추가 Scan URL을 가져오는 데 사용됩니다.

## Synchronizer connection option

기본적으로 validator는 BFT read를 위해 여러 Scan instance와 sequencer connection을 discover합니다. 여러 SV에 trust를 분산하므로 production에서 권장하는 configuration입니다.

### Scan proxy를 통한 BFT(권장)

<CantonDocsGlobalSynchronizerReferenceConfigurationReferenceL150 />


### PostgreSQL configuration(standalone Canton)

PostgreSQL에 연결된 standalone Canton participant의 configuration은 다음과 같습니다.

```
canton.participants.participant1.storage {
  type = postgres
  config {
    dataSourceClassName = "org.postgresql.ds.PGSimpleDataSource"
    properties = {
      serverName = "localhost"
      databaseName = "participant1_db"
      portNumber = "5432"
      user = ${POSTGRES_USER}
      password = ${POSTGRES_PASSWORD}
    }
  }
}
```

Canton은 connection pooling에 [HikariCP](https://github.com/brettwooldridge/HikariCP)를 사용합니다. Tuning 권장 사항은 [HikariCP pool sizing guide](https://github.com/brettwooldridge/HikariCP/wiki/About-Pool-Sizing)를 참조하세요.

### PostgreSQL SSL

다음 `PGSimpleDataSource` property로 database connection의 SSL을 활성화합니다.

- `ssl = true` -- SSL certificate 및 hostname 검증
- `sslmode = "verify-ca"` -- Root certificate를 기준으로 certificate chain 확인
- `sslrootcert = "path/to/root.cert"` -- Root CA certificate path

Mutual TLS의 경우 client certificate와 key를 가리키는 `sslcert` 및 `sslkey`를 추가합니다.

## TLS configuration

Canton API(Ledger API 및 Admin API)는 선택적인 mutual authentication과 함께 TLS를 지원합니다. Ledger API의 최소 server-side TLS configuration은 다음과 같습니다.

```
canton.participants.participant.ledger-api.tls {
  cert-chain-file = "./tls/ledger-api.crt"
  private-key-file = "./tls/ledger-api.pem"
  trust-collection-file = "./tls/root-ca.crt"
}
```

Client certificate authentication(mTLS)을 요구하려면 다음을 추가합니다.

```
canton.participants.participant.ledger-api.tls.client-auth {
  type = require
  admin-client {
    cert-chain-file = "./tls/admin-client.crt"
    private-key-file = "./tls/admin-client.pem"
  }
}
```

모든 private key는 PKCS#8 PEM format이어야 합니다. Minimum TLS version도 제한할 수 있습니다.

```
canton.participants.participant.ledger-api.tls.minimum-server-protocol-version = TLSv1.3
```

허용되는 cipher suite는 다음과 같이 지정합니다.

```
canton.participants.participant.ledger-api.tls.ciphers =
  [
    "TLS_AES_256_GCM_SHA384",
    "TLS_AES_128_GCM_SHA256",
    "TLS_CHACHA20_POLY1305_SHA256"
  ]
```

1.3 suite에서는 Java `jdk.tls.namedGroups` property를 사용하여 지원되는 key exchange를 사용자 지정합니다.

## Monitoring 및 observability

### Metrics endpoint

**Helm deployment**: Helm values에서 `metrics.enable: true`를 설정하여 `ServiceMonitor` custom resource를 생성합니다. Prometheus Operator가 필요합니다. 또는 port 10013을 대상으로 하는 Prometheus scrape annotation을 추가합니다.

**Docker Compose deployment**: Metric은 기본적으로 `http://validator.localhost/metrics`(validator app) 및 `http://participant.localhost/metrics`(participant)에서 활성화됩니다.

### Histogram

Metric은 OpenTelemetry로 구축되며 [Prometheus native histogram](https://prometheus.io/docs/specs/native_histograms/)으로 노출됩니다. Prometheus에서 `-enable-feature=native-histograms`로 활성화합니다. Regular histogram으로 fallback하려면 다음을 사용합니다.
