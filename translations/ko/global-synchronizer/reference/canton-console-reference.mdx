더 복잡한 debugging 및 disaster recovery를 위해 Canton node(participant, sequencer, mediator)의 console에 직접 접근해야 할 수 있습니다. 접근 절차는 다음과 같습니다.

요구 사항:

- Canton node process에 직접 접근할 수 있어야 함
- Canton binary

Console에 다음 banner가 표시되면 성공적으로 접근한 것입니다.

``` text
_____            _
/ ____|          | |
| |     __ _ _ __ | |_ ___  _ __
| |    / _` | '_ \| __/ _ \| '_ \
| |___| (_| | | | | || (_) | | | |
\_____\__,_|_| |_|\__\___/|_| |_|

Welcome to Canton!
```

## Participant console

1.  [Canton authentication 문서](/global-synchronizer/reference/security-configuration#configure-api-authentication-and-authorization-with-jwt)에 명시된 대로 authentication token을 가져옵니다.

2.  Participant의 port 5001 및 5002에 접근할 수 있는지 확인합니다.

3.  Configuration을 로컬 file `console.conf`에 추가합니다.
    <ExternalSpliceMainSpliceRstCodeDocsSrcDeploymentConsoleAccessNone40 />

4.  Docker command를 실행합니다.

## Sequencer console

{/* NETWORKVARS_START source="/snippets/networkvars/global-synchronizer/reference/canton-console-reference-3.mdx" */}
<Tabs>

<Tab title="DevNet (0.7.1)">

1.  Sequencer의 port 5008 및 5009에 접근할 수 있는지 확인합니다.

2.  Configuration을 로컬 file `console.conf`에 추가합니다.

```
canton {
  remote-sequencers {
    sequencer {
      public-api {
        port = 5008
        address = localhost
      }
      admin-api {
        port = 5009
        address = localhost
      }
    }
  }
  features.enable-preview-commands = yes
  features.enable-testing-commands = yes
  features.enable-repair-commands = yes
}
```
3.  Docker command를 실행합니다.

```bash
docker run -it --rm --network host -v $(pwd)/console.conf:/app/app.conf ghcr.io/digital-asset/decentralized-canton-sync/docker/canton:0.7.1 --console
```

## K8s cluster에서 접근

K8s cluster에서는 debug pod를 사용하여 cluster에서 console에 직접 접근할 수 있습니다.

먼저 다음을 사용하여 올바른 Canton version을 실행하는 pod를 생성할 수 있습니다.

<ExternalSpliceMainSpliceRstCodeDocsSrcDeploymentConsoleAccessBash166 />

여기서 `POD_NAME`은 participant, sequencer 또는 mediator pod의 이름입니다.

실행 중인 pod 내부에 들어가면 text editor를 설치하고 위에서 설명한 config file `console.conf`를 생성할 수 있습니다.
