## External KMS를 사용한 Participant key 관리

Default로 Canton Participant는 Participant 자체에서 생성하고 Participant가 사용하는 일반 database에 저장하는 cryptographic [key](/appdev/modules/m7-security)를 사용합니다. Key security를 개선하기 위해 external Key Management System(KMS)에서 key를 생성하고 저장하도록 Participant를 구성할 수 있습니다. 자세한 내용과 지원되는 KMS provider 목록은 공식 [Canton KMS 지원 documentation](/global-synchronizer/production-operations/kms-operations)을 참조하세요. Splice deployment의 일부로 deploy된 Participant는 KMS usage의 [External Key Storage](/global-synchronizer/production-operations/key-management) mode를 지원합니다.

아래에서는 external KMS에서 Participant key를 관리하도록 Validator를 구성하는 방법을 설명합니다. 이 guide는 Validator의 [Helm 기반 deployment](/global-synchronizer/deployment/validator-kubernetes)를 사용한다고 가정합니다. 현재 [Docker Compose 기반 deployment](/global-synchronizer/deployment/validator-docker-compose)에서는 KMS usage를 지원하지 않습니다.

### 기존 Validator를 external KMS 사용 방식으로 migration

기존 Participant를 "non-KMS-based" operation에서 "KMS-based" operation으로 migration하거나 한 KMS provider에서 다른 provider로 migration하는 것은 지원되지 않습니다. 주된 이유는 Participant의 root namespace key를 rotate할 수 없고, 잠재적으로 안전하지 않은 위치에서 KMS로 import하면 KMS 사용으로 얻는 security benefit이 줄어들기 때문입니다. 또한 일부 KMS provider는 기존 key import를 전혀 지원하지 않으며 KMS 자체에서 생성한 key만 관리할 수 있습니다.

KMS 사용 방식으로 전환할 때 권장하는 접근 방식은 다음과 같습니다.

1.  원하는 KMS configuration으로 fresh Validator를 처음부터 설정합니다. 이 guide의 나머지 부분을 참조하세요.
2.  기존 non-KMS Validator에서 새 KMS-enabled Validator로 관련 asset을 모두 transfer합니다.
3.  Non-KMS Validator를 retire합니다.
