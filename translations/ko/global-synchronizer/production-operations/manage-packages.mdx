# Daml Package 및 Archive 관리

## 개요

Package는 하나의 Daml project에 해당하는 compiled Daml code unit입니다. Package에는 compiled Daml-LF code가 들어 있습니다. 모든 package에는 고유한 `package-id`가 있습니다. Daml Archive(DAR) file은 main package와 main package가 depend하는 다른 모든 package로 구성됩니다. DAR에는 main package가 하나뿐이므로 main `package-id`로 DAR를 지칭할 수도 있습니다. App provider는 DAR collection 형태로 app을 배포합니다.

## DAR 관리

### DAR upload

DAR를 upload하려면 dars.upload Console Command를 사용합니다.

``` none
@ participant2.dars.upload("dars/CantonExamples.dar", vetAllPackages = false)
    res1: String = "69f6fc47c97947ec96f28e5a9c6cd368fd79d45e2e27298556073ef8809d5a2b"
```

App을 실행하는 모든 Participant Node는 app DAR가 공유되지 않으므로 이를 독립적으로 load해야 합니다.

### DAR 목록 조회

DAR 목록을 조회하려면 dars.list Console Command를 사용합니다.

<ExternalCantonMainDocsOpenTargetSnippetJsonDataParticipantHowtosOperatePackagesPackages1 />

<Note>
**canton-builtin-admin-workflow-ping** package는 Canton과 함께 제공되는 package입니다. 이 package에는 `participant.health.ping` Command가 사용하는 Daml template이 포함되어 있습니다.
</Note>

Package 목록을 filter하려면 `list` method에 criteria를 제공합니다. 예를 들어 **CantonExamples**라는 DAR의 description을 extract하려면 먼저 name으로 filter한 다음 `head`를 사용해 목록의 첫 element를 extract합니다.

``` none
@ val cantonExampleDar = participant2.dars.list(filterName = "CantonExamples").head
    cantonExampleDar : DarDescription = DarDescription(
      mainPackageId = "69f6fc47c97947ec96f28e5a9c6cd368fd79d45e2e27298556073ef8809d5a2b",
      name = "CantonExamples",
      version = "3.5.0",
      description = "CantonExamples"
    )
```

### DAR content 표시

DAR content를 표시하려면 dars.get_contents Console Command를 사용합니다.

``` none
@ val darContent = participant2.dars.get_contents(cantonExampleDar.mainPackageId)
    darContent : DarContents = DarContents(
      main = 69f6fc47c979...,
      name = CantonExamples,
      version = 3.5.0,
      description = CantonExamples,
      packages = Seq(
        6da1f43a10a1...,
        6f8e6085f576...,
    ..
```

Content에는 DAR의 name과 version, 그리고 dependency로 DAR에 포함된 package의 name과 version이 들어 있습니다.

<Note>
모든 DAR file에는 **daml-** prefix가 있는 Daml standard library package가 포함됩니다. 예를 들면 **daml-prim**입니다.
</Note>

## Package Vetting 관리

Command submission 시 Transaction에 관여하는 모든 Participant Node는 동일한 결론에 도달하도록 Transaction 해석에 필요한 package를 보유해야 합니다. Package Vetting Topology information을 통해 Participant Node는 자신이 지원하는 package를 다른 Participant Node에 알립니다. DAR file을 Participant Node에 upload하면 연결된 모든 Synchronizer에 vetting information이 publish되어 다른 Participant Node가 사용할 수 있게 됩니다. Vetted package 목록을 조회하려면 `topology.vetted_packages.list` Console Command를 사용합니다.

특정 package의 Synchronizer/Participant Node vetting state를 표시하려면 다음과 같이 결과를 filter합니다.

``` none
@ participant1.dars.upload("dars/CantonExamples.dar")
    res5: String = "69f6fc47c97947ec96f28e5a9c6cd368fd79d45e2e27298556073ef8809d5a2b"
```

``` none
@ participant2.dars.upload("dars/CantonExamples.dar")
    res6: String = "69f6fc47c97947ec96f28e5a9c6cd368fd79d45e2e27298556073ef8809d5a2b"
```

@ val mainPackageId = participant2.dars.list(filterName = "CantonExamples").head.mainPackageId

### Main DAR package unvet

Main DAR package 지원을 제거하려면 dars.vetting.disable Console Command를 사용합니다.

``` none
@ participant2.dars.vetting.disable(mainPackageId)
```

``` none
@ participant1.topology.vetted_packages.list().filter(_.item.packages.exists(_.packageId == mainPackageId)).map(r => (r.context.storeId, r.item.participantId))
    res10: Seq[(TopologyStoreId, ParticipantId)] = Vector(
      (Synchronizer(id = Right(value = da::1220a82692ab...::34-0)), PAR::participant1::12201ff69b1d...)
    )
```

<Warning>
Active Contract가 참조하는 package는 unvet할 수 없습니다. 이를 시도하면 `FAILED_PRECONDITION/TOPOLOGY_PACKAGE_ID_IN_USE` error가 발생합니다.
</Warning>

Package vetting을 다시 활성화하려면 dars.vetting.enable Console Command를 사용합니다.

## DAR validate

DAR validation을 사용하여 DAR에 포함된 package가 특정 Synchronizer에서 이미 load되고 vet된 package와 compatible한지 확인합니다. 예를 들어 새 template이 동일한 package, module 및 template name을 가진 기존 template을 다시 정의하면 invalid합니다. 이 endpoint는 current vetting state와 DAR의 compatibility를 validate하므로 Synchronizer가 Participant에 연결되어 있어야 합니다.

Default로 DAR는 upload 시 validate됩니다. DAR를 독립적으로 validate하려면 dars.validate Console Command를 사용합니다.

``` none
@ participant2.dars.validate("dars/CantonExamples.dar")
    res11: String = "69f6fc47c97947ec96f28e5a9c6cd368fd79d45e2e27298556073ef8809d5a2b"
```

<Note>
DAR file validation은 Participant Node를 변경하지 않으며 어떤 information도 persist되지 않습니다.
</Note>

## Package 및 DAR 제거

<div className="danger">

Package를 제거하면 다음을 비롯한 여러 issue가 발생할 수 있습니다.

- Upgrade된 context에서 사용하더라도 해당 package를 대상으로 처음 생성한 Contract를 사용할 수 없습니다.
- Verbose mode에서 archived Contract에 대한 Ledger API reporting을 수행할 수 없습니다. Historical Contract event를 report하는 데 해당 package가 여전히 필요하기 때문입니다.

**따라서 package가 사용된 적이 없거나 package에 대한 모든 reference가 pruning되었다고 확신하지 않는 한 production environment에서 package 또는 DAR를 제거해서는 안 됩니다.**

</div>

### DAR 제거

DAR 제거는 DAR와 연결된 main package만 제거하며 다른 package는 제거하지 않습니다.

다음 조건에서만 DAR를 제거할 수 있습니다.

- Package를 참조하는 Active Contract가 없습니다.
- DAR package를 depend하는 다른 package가 없습니다.
- DAR의 main package가 unvet 상태입니다.

#### Package 강제 제거

<div className="danger">

Package 강제 제거는 위험한 operation입니다. 따라서 package가 사용되지 않고 package에 대한 모든 reference가 pruning되었다고 확신하지 않는 한 production environment에서 package를 강제로 제거하지 마세요.

</div>

Canton은 개별 package 제거도 지원하여 user가 system을 더 세밀하게 제어할 수 있게 합니다. Package를 제거하려면 다음 조건이 충족되는지 확인하세요.

- Package가 사용되지 않습니다. 즉 해당 package에 대응하는 Active Contract가 없어야 합니다.
- Package가 unvet 상태입니다. 즉 해당 package에 대응하는 active vetting Transaction이 없어야 합니다.
- Participant administration에 package가 필요하지 않습니다. 예를 들어 **Ping** template이 포함된 package는 필요합니다.
