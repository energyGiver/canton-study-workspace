Canton Console은 Scala 기반 scripting 및 REPL framework인 [Ammonite](http://ammonite.io)를 기반으로 합니다. 입력하는 모든 Command는 유효한 Scala입니다. 따라서 다른 Scala program과 마찬가지로 loop를 작성하고, function을 정의하고, variable을 binding하며, operation을 조합할 수 있습니다.

이 페이지에서는 `.canton` script file 작성 및 실행 방법과 operator task 자동화에 사용하는 일반 pattern 등 scripting의 실용적인 측면을 설명합니다.

## Script file load 및 실행

Canton script는 관례적으로 `.canton` file extension을 사용합니다. 두 가지 방식으로 실행할 수 있습니다.

**시작 시 script 실행**

```bash
./bin/canton run myscript.canton -c myconfig.conf
```

Console을 시작하고 script를 실행한 뒤 종료합니다. Unattended automation의 표준 접근 방식입니다.

**Console 내부에서 script load**

Interactive session에서 Ammonite의 `interp.load` mechanism 또는 `utils` helper를 사용하여 script file을 load합니다.

<CantonGlobalSynchronizerCantonConsoleScriptingL63 />


Compiled JAR(예: Daml codegen binding)도 Console에 load할 수 있습니다.

<CantonGlobalSynchronizerCantonConsoleScriptingL69 />


**Bootstrap script**

Bootstrap script는 Console 시작 시 자동으로 실행됩니다.

```bash
./bin/canton -c myconfig.conf --bootstrap myscript.canton
```

`run`과 달리 bootstrap script가 완료된 후에도 Console이 열린 상태로 유지됩니다. Initial state를 설정한 다음 interactive mode로 전환할 때 유용합니다.

### External orchestration을 사용하는 scheduled task

Canton Console에는 built-in scheduler가 없습니다. 반복 task의 경우 `cron` 또는 Kubernetes CronJob과 같은 external scheduler에서 `.canton` script를 호출합니다.

```bash
# crontab entry: run health check every 5 minutes
*/5 * * * * /opt/canton/bin/canton run /opt/canton/scripts/health-check.canton -c /opt/canton/config/remote-participant.conf
```

이 접근 방식은 automation logic을 version control되는 `.canton` file에 유지하면서 검증된 scheduling infrastructure를 사용합니다.


<Note>
일부 Command는 Node process 자체의 local Console에서만 사용할 수 있습니다. Remote Console은 대부분의 administrative operation을 지원하지만 일부 low-level operation에는 local access가 필요합니다.
</Note>

## Production script tip

- Default에 의존하지 말고 항상 explicit timeout을 지정하세요. 무기한 hang되는 script보다 빠르게 실패하는 script가 diagnose하기 쉽습니다.
- 실패할 수 있는 operation, 특히 Network call 및 DAR upload를 `try/catch` block으로 감쌉니다.
- `println`으로 output을 log하거나 file에 기록합니다. Console은 기본적으로 output을 보존하지 않습니다.
- 가능한 경우 script를 idempotent하게 유지합니다. Script를 안전하게 다시 실행할 수 있으면 partial failure recovery가 간단합니다.
- Production에서 실행하기 전에 LocalNet 환경에서 script를 test합니다.
