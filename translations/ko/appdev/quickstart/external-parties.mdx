## 소개

External Party는 자체 cryptographic signing key를 제어하므로 Transaction 승인과 관련해 어떤 Participant Node도 신뢰할 필요가 없습니다. External Party는 Transaction signing을 완전히 제어하고 Transaction 승인에 대한 규제 준수를 보장하며 Participant Node operator로부터 독립적입니다.

## 사전 요구 사항

- Admin API credential이 있는 Participant Node에 대한 access
- Key 생성을 위한 OpenSSL 또는 동등한 tool
- API call을 위한 curl 또는 gRPC용 grpcurl

## External Party로 Transaction 제출

### 개요

한 단계로 제출하는 internal Party와 달리 External Party는 세 단계의 interactive submission process를 사용합니다.

1. **Prepare**: Participant Node에 Transaction 준비를 요청합니다.
2. **Sign**: External key로 Transaction hash에 서명합니다.
3. **Execute**: 서명된 Transaction을 제출합니다.

### 1단계: Transaction 준비

`InteractiveSubmissionService/PrepareSubmission` gRPC endpoint를 사용하여 Transaction을 준비합니다.

`Canton.Internal.Ping` template는 DAR file을 배포하지 않아도 모든 Canton Participant에서 사용할 수 있습니다. Ping template에는 `initiator`(External Party)와 `responder`(알려진 다른 Party)가 필요합니다.

Responder로 사용할 `app_user` Party를 Quickstart LocalNet에서 가져옵니다.

<ExternalCnQuickstartMainCnQuickstartRstCodeSdkDocsSharableSdkQuickstartOperateHowToOnboardExternalPartiesInQuickstartBash317 />

`Ping` contract를 제출합니다.

<ExternalCnQuickstartMainCnQuickstartRstCodeSdkDocsSharableSdkQuickstartOperateHowToOnboardExternalPartiesInQuickstartBash327 />

`user_id`는 `ledger-api-user`여야 하며, 이는 `LEDGER_TOKEN`에 사용된 JWT subject와 일치해야 합니다.
