# Explore the Canton Network Application Quickstart demo

## Business case

Canton Network(CN) Quickstart는 CN application의 build, test, deploy를 위한 development effort를 지원하는 scaffolding입니다. 모든 CN application이 해결해야 하는 infrastructure problem을 해결합니다. 여러분과 팀이 build system, deployment configuration, testing infrastructure가 아니라 application 구축에 집중할 수 있도록 CN Quickstart Application을 사용하세요.

### Core business operations

Quickstart는 Canton development pattern을 보여 주는 sample licensing app을 제공합니다. App에서 Provider는 service에 대한 time-based access를 판매합니다. User는 Canton Coin(CC)으로 지급하고 Canton Wallet을 통해 payment를 관리합니다.

App에는 네 Party가 관여합니다.

- License를 판매하는 **Application Provider**
- License를 구매하는 **Application User**
- [CC](https://www.canton.network/blog/canton-coin-a-canton-network-native-payment-application)를 사용하는 payment 처리 기반 **Amulet** token system
- Amulet payment system을 운영하는 Decentralized Synchronizer Operations Party인 **DSO Party**. CN에서는 Super Validator입니다.

Application은 다음 process로 License를 issue합니다.

#### Issuing a license

Provider가 onboard된 User를 위한 새 License를 생성합니다. License는 expired 상태로 시작하며 사용 전에 renew해야 합니다.

#### Requesting a license renewal

Provider가 renewal request를 생성하여 User를 위한 payment request를 만듭니다. 일치하는 CC payment request가 Ledger에 생성됩니다.

#### Paying for a license renewal

User가 Canton Wallet을 통해 payment를 approve하면 accepted payment Contract가 Ledger에 생성됩니다.

#### Renewing the license

Provider가 accepted payment를 처리하고 License를 새 expiration date로 update합니다.

## Overview

이 section에서는 CN App Quickstart 안의 Canton Network(CN) business operation에 익숙해지도록 돕습니다. App Quickstart application은 팀이 business need에 맞게 확장하도록 만들어졌습니다. App Quickstart에 익숙해지면 technology choice와 application design을 검토하여 필요한 변경을 결정하세요. Technology와 design decision은 궁극적으로 여러분의 몫입니다.

오류를 발견하면 Canton Network 담당자에게 문의하세요.

## Prerequisites

Demo를 시작하기 전에 [CN App Quickstart](/appdev/quickstart/prerequisites)를 설치하세요.

## Walkthrough

CN App Quickstart는 business need에 따라 authorization 사용 여부를 선택할 수 있습니다. `quickstart` subdirectory에서 `make setup` Command로 authorization을 toggle합니다. `make setup`은 Observability와 OAUTH2 enable 여부, Party hint를 묻습니다. 이 demo에서는 `TEST MODE`를 disable하고 default Party hint를 사용하며 OAUTH2가 enable된 경우와 disable된 경우를 모두 보여 줍니다. OAUTH2로 인해 차이가 있을 때 두 path를 차례로 표시합니다. 자신의 path를 따르고 다른 path는 무시하면 됩니다. Observability를 enable할 수 있지만 이 demo에는 필요하지 않습니다.

**Choose your adventure:**

OAUTH2 **없이** `make setup`:

![Make setup no auth](/images/docs_website/make-setup-noauth.png)

OAUTH2 **사용** `make setup`:

![Make setup with auth](/images/docs_website/make-setup-with-oauth.png)

### Login

**OAUTH2 disabled**

OAUTH2가 **disabled**이면 homepage에 간단한 login field가 나타납니다. User field에 "app-provider"를 입력하여 `AppProvider`로 login합니다.

![CN App Quickstart Login screen without Auth](/images/docs_website/01-login-app-qs-noauth.png)

**OAUTH2 enabled**

OAUTH2가 **enabled**이면 homepage에서 Keycloak OAuth 2.0 portal을 통해 login하라는 prompt가 나타납니다.

![CN App Quickstart Login screen with Auth](/images/docs_website/01-login-app-qs-auth.png)

`AppProvider` username은 “app-provider”이고 password는 "abc123"(모두 lowercase)임을 기억하세요.

Keycloak을 사용하여 `app-provider`로 login합니다.

Login credential을 입력합니다. Username: app-provider, password: abc123

![AppProvider login screen](/images/docs_website/login-app-provider-view.png)

### The App Installs Menu

Login 후 menu에서 **AppInstalls**를 선택합니다.

![App Installs view](/images/docs_website/qs-demo-app-installs-view.png)

Terminal을 열어 App Install Request를 생성합니다.

`/quickstart/`에서 다음을 실행합니다.

    make create-app-install-request

이 Command는 Participant를 대신하여 App Installation Request를 생성합니다.

![App Install Request](/images/docs_website/04-create-install-req.png)

<Note>
Machine 성능이 `LocalNet`을 hosting하기에 부족하거나 Docker container가 responsive하지 않으면 response에 status code 404 또는 000 failure가 표시될 수 있습니다(아래 image 참조). Docker memory limit을 최소 8 GB로 늘리면 `LocalNet` container가 올바르게 작동할 수 있습니다.
</Note>

![App Install Request error](/images/docs_website/05-error-app-install.png)

Browser로 돌아갑니다.

### AppInstallRequest

Install request가 list에 나타납니다.

**Accept**를 click합니다.

![accept request](/images/docs_website/accept-awaiting-request.png)

`AppInstallRequest`가 accept됩니다.

![accepted request](/images/docs_website/success-accepted-appinstallrequest.png)

Action이 Cancel과 Create license로 update됩니다.

### Create a license

**Create License**를 click합니다. License가 생성되고 “# Licenses” field가 update됩니다.

![create license](/images/docs_website/created-license.png)

다음으로 Licenses menu로 이동하여 **Renewals**를 선택합니다.

![Licenses view](/images/docs_website/new-license-select-renewals.png)

License를 renew하는 option이 있는 "License Renewal Request” modal이 열립니다.

![license renewal request modal](/images/docs_website/license-renewal-request-modal.png)

**New**를 click하여 "Renew License" modal을 엽니다.

![renew license modal](/images/docs_website/renew-license-modal.png)

Modal에서 License renewal day 수, fee, License 준비 시간, License settle 시간을 설정합니다. 계속하려면 description을 추가해야 합니다.

"Prepare in"은 sender(app-user)가 해당 time 전에 allocation을 accept해야 함을 나타냅니다. "Settle in"은 Provider가 `completeRenewal`을 수행할 수 있는 time입니다. 이후 allocation이 expire됩니다.

**Issue License Renewal Request**를 click합니다.

![new license renewal request](/images/docs_website/new-license-renewal-request.png)

Daml Contract에 따라 License는 expired 상태로 생성됩니다. License를 activate하려면 renewal payment request를 issue해야 합니다.

### Make a payment

Payment를 하려면 [http://wallet.localhost:2000/allocations](http://wallet.localhost:2000/allocations)의 Canton Wallet로 이동하고 prompt가 나타나면 `app-user`로 login합니다.

Wallet location은 다음 방법으로 찾을 수 있습니다.

1.  [LocalNet Application UIs reference](/sdks-tools/development-tools/localnet#application-uis)를 읽습니다.
2.  App Provider의 "Tenants" menu로 이동합니다.

![AppProvider Tenants menu](/images/docs_website/app-provider-tenants.png)

3.  App에 `app-user`로 login하고 Licenses menu로 이동한 다음 **Renewals** action을 click합니다.

![AppUser Licenses menu](/images/docs_website/app-user-licenses-menu.png)

Prompt가 나타나면 CC Wallet에 `app-user`로 login합니다.

![Canton Coin Wallet login](/images/docs_website/canton-coin-wallet-app-user-log-in.png)

Wallet에 CC가 없으면 amount를 입력하고 **TAP**을 click합니다. 잠시 후 available balance가 자동으로 update됩니다.

![Tap for CC](/images/docs_website/tap-canton-wallet.png)

CC Wallet에 fund가 들어오면 "Allocations" menu로 이동하여 "Allocate before" time이 expire되기 전에 "Allocation Request"를 accept합니다.

![CC Wallet accept allocation](/images/docs_website/canton-coin-wallet-allocations-menu.png)

Allocation request가 accept되면 새 "Allocations" section이 나타납니다. 이 section은 `licenseFeePayment` information을 표시합니다.

![CC Wallet accepted allocation](/images/docs_website/canton-coin-wallet-accepted-allocation.png)

### Renew the license

`AppProvider`로 Quickstart에 돌아갑니다. Licenses menu에서 **Renewals**를 선택합니다. License Renewals Request modal이 열립니다. Green **Complete Renewal** button을 click합니다.

![complete renewal after payment](/images/docs_website/app-provider-complete-renewal-after-payment.png)

License renewal이 성공적으로 완료되었다는 confirmation이 나타납니다.

![renewal success after payment](/images/docs_website/license-renewal-completed-successfully.png)

`AppProvider`에서 logout하고 `AppUser`로 login합니다.

**OAUTH2 disabled**

OAUTH2가 disabled이면 `app-user`로 login하기만 하면 됩니다.

![AppUser login screen without Auth](/images/docs_website/login-app-user-noauth.png)

**OAUTH2 enabled**

OAUTH2가 enabled이면 app-user username/password를 사용하여 login합니다.

![login screen](/images/docs_website/01-login-app-qs-auth.png)

Username “app-user", password “abc123”으로 `AppUser` login합니다.

![AppUser login screen](/images/docs_website/appuser-auth-login-view.png)

AppInstall이 이제 accepted 상태로 표시됩니다.

![accepted AppInstall](/images/docs_website/accepted-app-install.png)

License가 active 상태로 표시됩니다.

![logout AppProvider](/images/docs_website/app-user-license-active.png)

축하합니다. Canton Wallet의 payment allocation으로 License를 성공적으로 생성하고 activate했습니다!

Canton Console은 실행 중인 application Ledger에 연결됩니다. Console을 사용하면 developer가 UI를 우회하여 CN과 더 직접적으로 상호 작용할 수 있습니다. 예를 들어 Canton Console에서 Participant에 연결하여 Participant location과 Synchronizer domain을 확인할 수 있습니다.

`quickstart/` directory의 terminal에서 Canton Console을 activate합니다. 다음을 실행합니다.

    make canton-console

Console이 시작되면 각각 `participants`와 `participants.all` Command를 실행합니다.

    participants

Participant를 상세하게 categorize한 결과를 반환합니다.

![Participant location in the ledger](/images/docs_website/canton-console-participants.png)

    participants.all

모든 Participant reference list를 표시합니다.

![Participant synchronizer](/images/docs_website/canton-console-participants-all.png)

`LocalNet`에서는 list에 있는 어느 Participant에도 연결할 수 있습니다. 다음을 사용하여 App User Validator에 연결합니다.

    `app-user`

![App User](/images/docs_website/app-user.png)

Error가 발생하면 backtick을 사용했는지 다시 확인하세요.

App Provider는 다음으로 연결할 수 있습니다.

    `app-provider`

![App Provider](/images/docs_website/app-provider.png)

다음을 사용하여 Global Synchronizer를 simulate하는 Super Valdiator에 연결합니다.

    `sv`

![super validator](/images/docs_website/sv.png)

Canton Console은 Canton Network Validator health를 표시하는 diagnostic tool도 제공합니다.

    health.status

![Ping yourself](/images/docs_website/health-status.png)
