# JSON Ledger API 사용

## 개요

이제 CN Quickstart를 확장하여 LocalNet과 직접 상호 작용할 준비가 되었습니다. 실행 중인 LocalNet에 OAuth2 authentication을 적용하고 Party 생성, DAR upload, Contract 생성, Canton Coin(Amulet) 통합을 programmatic하게 수행하는 방법을 알아봅니다. 이 과정을 마치면 자체 Canton Network Application을 build하는 데 필요한 핵심 API pattern을 직접 경험하게 됩니다.

## Prerequisite

이 guide에는 Digital Asset Package Manager가 필요합니다. [DPM](/sdks-tools/cli-tools/dpm)의 installation instruction을 따르세요.

Quickstart installation과 Explore the demo tutorial도 완료해야 합니다. Quickstart가 모든 CN App에 필요한 tool을 제공하여 Canton Network development를 bootstrap하는 방식을 더 잘 이해하려면 Developer Journey lifecycle도 읽는 것이 좋습니다.

## LocalNet interaction과 Explore the demo의 차이, App 사용과 developer skill

Demo에서는 user로서 web interface를 통해 LocalNet과 상호 작용했습니다. 이제 API를 통해 LocalNet을 직접 제어하고 ScratchNet, TestNet 및 그 이후 환경에서 build할 기반이 되는 network infrastructure를 programmatic하게 관리하는 방법을 알아봅니다.

## LocalNet environment 및 authentication

### Environment 확인

Quickstart Application이 build되어 실행 중이어야 합니다. Terminal에서 `make status`를 사용하여 모든 service가 작동하는지 확인합니다.

![Make status 화면](/images/docs_website/terminal-make-status.png)

### Port mapping

#### 보안 고려 사항

`LocalNet`의 port mapping은 `AdminAPI` port와 `Postgres` port를 노출하며, 둘 다 일반적으로 security risk가 됩니다. 하지만 local developer machine에서 실행할 때 이 port에 직접 access할 수 있으면 유용할 수 있습니다. Local이 아닌 deployment의 configuration을 준비할 때는 이 port를 노출해서는 안 됩니다. Port suffix는 environment variable로 정의됩니다. 비활성화하려는 port mapping이 있으면 해당 file에서 관련 Docker `port`: entry를 찾아 제거할 수 있습니다.

#### JSON API port

(2975, 3975, 4975): Daml operation 및 Smart Contract deployment

#### Validator API port

(2903, 3903, 4903): Status monitoring

### OAuth2 및 token 관리

#### 개요

LocalNet은 [http://keycloak.localhost:8082](http://keycloak.localhost:8082)의 Keycloak과 `AppUser`, `AppProvider` 두 realm을 OAuth2 authentication에 사용합니다.
Username과 password `admin`을 사용하여 이 port의 [Keycloak](/appdev/quickstart/deploy-to-devnet#keycloak)에 login합니다.

![Keycloak admin login 화면](/images/docs_website/keycloak-admin-login.png)

## JSON API tutorial

이 tutorial에서는 JWT token을 요청하고 API call에 Bearer token으로 포함하여 Quickstart Web App에서 수행한 단계를 API call로 재현합니다. `quickstart/` directory에서 Application과 tool을 시작합니다.

### Log capture 시작

`make capture-logs`

Log capture를 해당 terminal window에서 계속 실행합니다. 새 terminal window에서 `make start`로 Quickstart Application을 실행합니다. 완료되면 이 window를 작업용 terminal로 사용할 수 있습니다. `make start`가 완료되면 새 terminal window를 열어 lnav를 시작합니다. `lnav logs/*.clog`로 lnav를 시작하여 log를 capture하고 분석합니다. Clog가 없으면 `make stop && make clean-all`을 실행한 다음 `make start`를 다시 실행해 보세요. 또는 이 guide를 시작하여 Ledger에 Transaction을 만들 수 있습니다. 그러면 clog가 자동 생성됩니다. 이 command는 작업 중 Transaction trace, 문제 debug, system 동작 monitoring을 위해 lnav를 실행합니다. Lnav는 해당 terminal window에서 계속 실행하세요.

#### Lnav 안내

Lnav 탐색과 custom format 이해에 관한 자세한 안내는 [lnav를 사용한 debugging 및 troubleshooting](/appdev/quickstart/lnav)을 참조하세요.

### `daml shell`로 돌아가기

`LicenseRenewalRequest`는 `AllocationRequest interface`를 구현합니다.

User는 payment를 충족하도록 100 CC token을 allocate해야 합니다.

<ExternalCnQuickstartMainCnQuickstartRstCodeSdkDocsSharableSdkQuickstartOperateJsonApiBash808 />

Return에 "\<empty\>"가 표시되면 몇 분 기다린 후 다시 시도하세요. 최대 15분이 걸릴 수 있습니다. 이는 Participant Query Store(PQS)의 작동 방식으로 인한 정상적인 Canton Network 동작입니다. Holding 또는 다른 on-ledger activity가 `daml shell`에 표시되려면 먼저 Transaction이 Ledger에서 처리되고, PQS가 새 event를 확인하도록 Participant를 poll한 후 database를 update해야 합니다. Sync가 완료되면 query가 새 data를 반환합니다.

이 단계를 완료하려면 `amount` 값이 100보다 커야 합니다.

LocalNet에서 Canton Wallet은 각 round마다 token을 자동으로 보충합니다. Amount가 100 미만으로 표시되면 Wallet에 충분한 amount가 쌓이도록 몇 분 기다리기만 하면 될 가능성이 큽니다.

선택 사항: 더 자세한 내용을 확인하려면 Holding Contract ID를 call합니다.

[http://wallet.localhost:2000/allocations](http://wallet.localhost:2000/allocations)의 Canton Wallet UI로 이동합니다.

`app-user`로 login하며 password는 `abc123`입니다.

Demo에서는 Web App의 Backend process가 allocation을 대신 완료했습니다. 이제 allocation request를 수동으로 작성해야 합니다.

UI에 allocation request가 표시되더라도 Daml Shell allocation Contract의 allocation을 수동으로 생성해야 합니다.

![Allocation 수동 생성](/images/docs_website/json-api-create-allocation.png)

앞에서 언급한 `Payload` metadata를 사용하여 빨간색으로 둘러싸인 모든 field를 채웁니다.

- **Transfer Leg ID:** `licenseFeePayment`
- **Settlement Ref ID:** `settlementRef.id`
- **Recipient:** `receiver`
- **Executor:** `executor`
- **Amount:** `100`
- **Requested At:** `requestedAt`
- **Settle before:** `settleBefore`
- **Allocate before:** `allocateBefore`

Settlement meta와 Transfer leg meta 각각에 두 개의 custom entry를 추가합니다.

- **Key:** `cn-quickstart.example.org/licenseNum`
- **Value:** `1`
- **Key:** `splice.lfdecentralizedtrust.org/reason`
- **Value:** `License renewal payment`

값을 quote로 감싸지 마세요. Canton Wallet이 escaped quote를 추가합니다.

두 key/value pair를 양쪽 meta option에 모두 넣습니다.

필요한 정보는 Daml Shell의 LicenseRenewalRequest Contract `payload` field에서 확인합니다.

`Requested At`, `Settle before`, `Allocate before` 시간에는 "Z" 앞에 "."와 0 여섯 개를 수동으로 입력해야 합니다.

예를 들어 `requestedAt: 2025-10-29T20:38:16Z`는 `2025-10-29T20:38:16.000000Z`가 됩니다.

모든 정보를 입력한 후 request를 보냅니다.
