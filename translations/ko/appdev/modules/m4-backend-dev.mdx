backend는 frontend와 Canton ledger 사이의 layer입니다. Command를 submit하고 Transaction을 읽으며 contract state를 query합니다.

이 페이지에서는 [cn-quickstart](https://github.com/digital-asset/cn-quickstart)를 작동하는 예시로 사용합니다. cn-quickstart는 Canton Network에서 software licensing workflow를 구현하는 full-stack reference application입니다. Spring Boot backend, React frontend, Daml smart contract, local 실행 또는 DevNet deploy에 필요한 모든 configuration을 포함합니다. 여기서 보여 주는 Ledger API 연결, Command submission, PQS query, error handling pattern은 모든 Canton backend에 적용되지만 code sample은 [cn-quickstart backend](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend)에서 직접 가져오므로 실제 작동 context에서 확인할 수 있습니다.

## Backend Language

cn-quickstart는 Spring Boot 기반 Java backend를 사용합니다. Java는 first-class code generation support인 `dpm codegen-java`를 제공합니다.

`dpm codegen-js`를 통해 TypeScript도 지원합니다. TypeScript backend는 gRPC-js 또는 JSON API를 통해 동일한 Ledger API를 사용하며 frontend와 backend에서 하나의 언어를 선호하는 팀에 적합할 수 있습니다.

## Ledger API 연결

Ledger API는 Validator의 Participant Node가 공개하는 service입니다. backend는 authenticated client로 연결되어 한 명 이상의 Party를 대신해 행동합니다.

cn-quickstart에서 [`LedgerApi.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/ledger/LedgerApi.java)가 이 connection을 관리합니다. constructor는 모든 호출에 bearer token을 연결하는 authentication interceptor가 있는 gRPC channel을 build합니다.

```java
ManagedChannelBuilder<?> builder = ManagedChannelBuilder
        .forAddress(ledgerConfig.getHost(), ledgerConfig.getPort())
        .usePlaintext();
builder.intercept(new Interceptor(tokenProvider));
ManagedChannel channel = builder.build();

submission = CommandSubmissionServiceGrpc.newFutureStub(channel);
commands = CommandServiceGrpc.newFutureStub(channel);
```

`Interceptor` class는 호출할 때마다 gRPC metadata에 bearer token을 연결합니다.

```java
@Override
public <ReqT, RespT> ClientCall<ReqT, RespT> interceptCall(
        MethodDescriptor<ReqT, RespT> method, CallOptions callOptions, Channel next) {
    ClientCall<ReqT, RespT> clientCall = next.newCall(method, callOptions);
    return new ForwardingClientCall.SimpleForwardingClientCall<>(clientCall) {
        @Override
        public void start(Listener<RespT> responseListener, Metadata headers) {
            headers.put(AUTHORIZATION_HEADER, "Bearer " + tokenProvider.getToken());
            super.start(responseListener, headers);
        }
    };
}
```

LocalNet에서는 token을 Keycloak에서 가져옵니다. production에서는 OAuth2 provider에서 가져옵니다.

## Command Submission

Command는 ledger에 write하는 방법입니다. contract 생성과 choice exercise라는 두 가지 주요 operation이 있습니다.

### Contract 생성

contract를 생성하려면 template identifier와 payload로 `Create` Command를 build한 다음 submit합니다. cn-quickstart에서는 `LedgerApi.create()` method가 이를 처리합니다.

```java
public <T extends Template> CompletableFuture<Void> create(T entity, String commandId) {
    CommandsOuterClass.Command.Builder command = CommandsOuterClass.Command.newBuilder();
    ValueOuterClass.Value payload = dto2Proto.template(entity.templateId()).convert(entity);
    command.getCreateBuilder()
        .setTemplateId(toIdentifier(entity.templateId()))
        .setCreateArguments(payload.getRecord());
    return submitCommands(List.of(command.build()), commandId)
        .thenApply(submitResponse -> null);
}
```

`dto2Proto` converter는 생성된 Java class를 Protobuf value로 변환합니다. `commandId`는 Ledger API가 deduplication에 사용하는 UUID입니다.

### Choice Exercise

choice를 exercise하려면 Contract ID와 choice argument가 필요합니다. `exerciseAndGetResult()` method는 `Exercise` Command를 build하고 Transaction result를 기다리는 `CommandService`를 통해 submit합니다.

```java
CommandsOuterClass.Command.Builder cmdBuilder = CommandsOuterClass.Command.newBuilder();
ValueOuterClass.Value payload =
    dto2Proto.choiceArgument(choice.templateId(), choice.choiceName()).convert(choice);

cmdBuilder.getExerciseBuilder()
    .setTemplateId(toIdentifier(choice.templateId()))
    .setContractId(contractId.getContractId)
    .setChoice(choice.choiceName())
    .setChoiceArgument(payload);
```

choice를 exercise하는 REST endpoint는 이러한 요소를 결합합니다. 다음은 [`LicenseApiImpl.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/service/LicenseApiImpl.java)가 license를 expire하는 방식입니다.

```java
@Override
public CompletableFuture<ResponseEntity<String>> expireLicense(
        String contractId, String commandId, LicenseExpireRequest request) {
    return auth.asAuthenticatedParty(party -> {
        return damlRepository.findLicenseById(contractId).thenCompose(optContract -> {
            var license = ensurePresent(optContract,
                "License not found for contract %s", contractId);
            License_Expire choice = new License_Expire(
                new Party(auth.getAppProviderPartyId()),
                toTokenStandardMetadata(request.getMeta().getData()));
            return ledger.exerciseAndGetResult(license.contractId, choice, commandId)
                .thenApply(result -> ResponseEntity.ok("License expired successfully"));
        });
    });
}
```

pattern은 PQS에서 contract를 lookup하고, 생성된 code에서 choice object를 build한 다음, Ledger API를 통해 submit하는 것입니다.

### Contract ID 처리

모든 Active Contract에는 unique Contract ID가 있습니다. choice를 exercise하려면 target contract의 ID가 필요합니다. backend는 PQS를 query하거나 Transaction stream에서 읽어 Contract ID를 얻습니다. cn-quickstart REST API는 Contract ID를 URL path로 전달합니다. 예를 들어 `POST /api/licenses/{contractId}/expire`를 사용합니다.

Contract ID는 opaque string입니다. 수동으로 parse하거나 구성하지 마세요.

## PQS Query

read operation의 경우 cn-quickstart backend는 Ledger API 대신 PQS를 query합니다. PQS는 Validator가 hosting하는 Party에게 보이는 ledger state를 반영하는 PostgreSQL database를 유지합니다.

### Pqs Adapter

[`Pqs.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/pqs/Pqs.java)는 Spring의 `JdbcTemplate`을 wrapping하고 PQS의 `active()` table-valued function을 사용해 Active Contract를 query합니다.

```java
public <T extends Template> CompletableFuture<List<Contract<T>>> active(Class<T> clazz) {
    Identifier identifier = Utils.getTemplateIdByClass(clazz);
    String sql = "select contract_id, payload from active(?)";
    return runAndTraceAsync(ctx, () ->
        jdbcTemplate.query(sql, new PqsContractRowMapper<>(identifier),
            identifier.qualifiedName())
    );
}
```

`active()` function은 `quickstart_licensing:Licensing.License:License` 같은 qualified template name을 받아 해당 type의 모든 Active Contract를 반환합니다. 각 row에는 `contract_id`와 JSON `payload`가 있습니다.

filtered query의 경우 `activeWhere()`가 `WHERE` clause를 추가합니다.

```java
public <T extends Template> CompletableFuture<List<Contract<T>>> activeWhere(
        Class<T> clazz, String whereClause, Object... params) {
    Identifier identifier = Utils.getTemplateIdByClass(clazz);
    String sql = "select contract_id, payload from active(?) where " + whereClause;
    return runAndTraceAsync(ctx, () ->
        jdbcTemplate.query(sql, new PqsContractRowMapper<>(identifier),
            combineParams(identifier.qualifiedName(), params))
    );
}
```

### Domain-Specific Query

[`DamlRepository.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/repository/DamlRepository.java)는 higher-level query를 build합니다. 예를 들어 `findActiveLicenses()`는 하나의 SQL query에서 license를 renewal request 및 allocation contract와 join합니다.

```sql
SELECT license.contract_id    AS license_contract_id,
       license.payload        AS license_payload,
       renewal.contract_id    AS renewal_contract_id,
       renewal.payload        AS renewal_payload,
       allocation.contract_id AS allocation_contract_id
FROM active(?) license
LEFT JOIN active(?) renewal ON
    license.payload->>'licenseNum' = renewal.payload->>'licenseNum'
    AND license.payload->>'user' = renewal.payload->>'user'
LEFT JOIN active(?) allocation ON
    renewal.payload->>'requestId' =
        allocation.payload->'allocation'->'settlement'->'settlementRef'->>'id'
WHERE license.payload->>'user' = ? OR license.payload->>'provider' = ?
ORDER BY license.contract_id
```

PQS는 contract payload를 JSONB로 저장하므로 PostgreSQL의 `->` 및 `->>` operator를 사용해 contract field를 filter하고 join합니다. 자주 query하는 JSON path에는 performance를 위해 PostgreSQL index를 추가할 수 있습니다.

## Transaction 읽기

Ledger API는 backend가 구독할 수 있는 Transaction stream도 공개합니다. 각 Transaction에는 해당 Party에게 보이는 생성 및 archive contract가 포함됩니다. PQS polling 대신 real-time event processing이 필요할 때 유용합니다.

Transaction stream subscription은 gRPC server streaming을 사용합니다. [docs-website quickstart](https://github.com/DACH-NY/docs-website)의 pattern은 다음과 같습니다.

```java
UpdateServiceGrpc.UpdateServiceStub updateServiceStub = UpdateServiceGrpc.newStub(channel);
updateServiceStub.getUpdates(getUpdatesRequest.toProto(), new StreamObserver<>() {
    public void onNext(UpdateServiceOuterClass.GetUpdatesResponse r) {
        GetUpdatesResponse response = GetUpdatesResponse.fromProto(r);
        response.getTransaction().ifPresent(transaction -> {
            for (Event event : transaction.getEvents()) {
                if (event instanceof CreatedEvent createdEvent) {
                    Iou.Contract contract = Iou.Contract.fromCreatedEvent(createdEvent);
                    // update local cache or trigger side effects
                } else if (event instanceof ArchivedEvent archivedEvent) {
                    // remove from local cache
                }
            }
        });
    }
    public void onError(Throwable throwable) { /* handle error */ }
    public void onCompleted() { /* stream ended */ }
});
```

cn-quickstart에서는 PQS가 read-side projection을 처리하므로 backend가 자체 event-sourced state를 유지하지 않습니다. PQS를 사용하지 않는다면 Transaction을 streaming하고 자체 projection을 유지하는 방식이 대안입니다.

## Error Handling

Canton은 structured error code를 사용합니다. Command가 실패하면 Ledger API가 Canton-specific error code가 있는 gRPC `StatusRuntimeException`을 반환합니다. 일반적인 category는 다음과 같습니다.

- **NOT_FOUND** -- Contract ID가 존재하지 않거나 submitting Party에게 보이지 않음
- **ALREADY_EXISTS** -- duplicate Command가 submit됨. Command는 Command ID로 deduplicate됩니다
- **INVALID_ARGUMENT** -- Command payload가 template 또는 choice signature와 일치하지 않음
- **FAILED_PRECONDITION** -- contract를 읽은 시점과 choice를 exercise한 시점 사이에 archive됨 (contention)

Java에서 `StatusRuntimeException`을 catch하고 status code를 검사합니다.

```java
import io.grpc.StatusRuntimeException;
import io.grpc.Status;

try {
    ledger.exerciseAndGetResult(contractId, choice, commandId).join();
} catch (CompletionException e) {
    if (e.getCause() instanceof StatusRuntimeException sre) {
        if (sre.getStatus().getCode() == Status.Code.NOT_FOUND) {
            // contract was archived — re-query PQS and retry
        }
    }
}
```

contention error의 경우 retry strategy로 문제가 해결되는 경우가 많습니다. PQS에서 현재 Contract ID를 다시 읽은 다음 Command를 다시 submit합니다.

<Note>
각 새 submission에 unique Command ID를 설정하세요. Ledger API는 이 ID로 Command를 deduplicate하므로 실제로 성공했지만 response가 transit 중 유실된 Command를 backend가 retry하는 경우 double-submission을 방지합니다.
</Note>

## cn-quickstart의 Backend Architecture

cn-quickstart backend는 [`backend/src/main/java/com/digitalasset/quickstart/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart) 아래에서 다음 module structure를 따릅니다.

- [`service/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/service) -- REST endpoint implementation. 각 endpoint는 PQS query 또는 Ledger API Command를 결합합니다.
- [`ledger/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/ledger) -- gRPC Ledger API client. Validator에 Command를 submit합니다.
- [`repository/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/repository) -- domain-specific PQS query method입니다.
- [`pqs/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/pqs) -- low-level SQL generation 및 PostgreSQL access입니다.
- [`utility/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/utility) -- JSON configuration, tracing, helper method입니다.
- [`security/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/security) -- OAuth2 bearer token validation 및 Party authentication입니다.
- [`config/`](https://github.com/digital-asset/cn-quickstart/tree/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/config) -- Spring Boot configuration property입니다.

이 structure는 read concern인 PQS와 write concern인 Ledger API를 명확히 분리하면서 REST layer를 얇게 유지합니다.

## 실습: License Comment 추가

이 실습에서는 cn-quickstart에 comment 기능을 추가합니다. user는 license에 comment를 post하고 해당 license의 모든 comment를 볼 수 있게 됩니다. 이 기능은 Daml model, code generation, OpenAPI spec, PQS query, REST endpoint라는 backend의 모든 layer를 다룹니다.

완료하면 ledger에 `LicenseComment` contract를 생성하고 PQS를 통해 다시 읽는 `/licenses/{contractId}/comments` API가 작동합니다.

### Step 1: Daml Template 정의하기

새 file `quickstart/daml/licensing/daml/Licensing/LicenseComment.daml`을 생성합니다.

<DamlAppdevModulesM4BackendDevL261 />

`commenter`가 Signatory이므로 comment를 작성하는 사람만 생성할 수 있습니다. `provider`와 `user`는 모두 Observer이므로 자신의 license에 달린 comment를 볼 수 있습니다. `licenseNum` field는 Contract ID reference 없이 comment를 특정 license에 연결합니다. Contract ID를 참조하면 license가 renewal되거나 archive될 때 link가 끊어질 수 있습니다.

dual Signatory인 `signatory provider, user`를 사용하는 [`Licensing/License.daml`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/daml/licensing/daml/Licensing/License.daml)의 `License` template과 비교해 보세요. comment에는 commenter의 authority만 필요하므로 더 쉽게 생성할 수 있으며 multi-party workflow가 필요하지 않습니다.

### Step 2: Build 및 Java Binding 생성

새 Daml module을 compile하고 Java binding을 다시 생성합니다. cn-quickstart 밖에서 작업한다면 `dpm`을 직접 사용하세요.

```bash
dpm build
dpm codegen-java <DAR-file> -o <output-dir>
```

cn-quickstart에서는 Gradle build가 두 step을 모두 처리합니다. Daml build task를 실행하면 `.daml` file을 DAR로 compile한 다음 transcode codegen plugin을 실행해 Java class를 생성합니다.

```bash
./gradlew :daml:build
```

이 step 후에는 `quickstart_licensing.licensing.licensecomment` package의 `backend/build/generated-daml-bindings/` 아래에 생성된 `LicenseComment` Java class가 있습니다. 생성된 class는 getter method 대신 public final field인 `getProvider`, `getUser`, `getLicenseNum` 등을 사용합니다. 이는 cn-quickstart 전체에서 사용하는 transcode codegen style입니다.

GET endpoint는 license의 `licenseNum`을 lookup하기 위한 Contract ID만 받습니다. POST endpoint는 `renewLicense` 및 `expireLicense`와 같은 convention에 따라 Ledger API deduplication용 `commandId`도 받습니다.

`tags: [Licenses]`를 사용해 기존 license operation과 이 endpoint를 group화합니다. cn-quickstart OpenAPI generator는 path가 `/licenses/`로 시작하는 모든 endpoint에서 `LicensesApi` Java interface를 생성하므로 새 method가 `LicenseApiImpl`이 이미 구현하는 같은 interface에 나타납니다.

spec을 update한 후 Spring server stub을 다시 생성합니다.

```bash
./gradlew openApiGenerate
```

이 Command는 `common/openapi.yaml`을 읽고 생성한 interface와 model class를 `backend/build/generated-spring/`에 기록합니다. 새 `listLicenseComments` 및 `addLicenseComment` method는 `LicensesApi` interface에 나타나고 `LicenseComment` 및 `AddCommentRequest` model class는 `org.openapitools.model`에 생성됩니다.

### Step 4: PQS Query 추가

license number로 comment를 찾는 method를 [`DamlRepository.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/repository/DamlRepository.java)에 추가합니다. license filtering에 사용하는 것과 같은 `activeWhere()` pattern을 따릅니다.

```java
public CompletableFuture<List<Contract<LicenseComment>>> findCommentsByLicenseNum(int licenseNum) {
    return pqs.activeWhere(
        LicenseComment.class,
        "payload->>'licenseNum' = ?",
        String.valueOf(licenseNum)
    );
}
```

PQS는 모든 contract payload를 JSON으로 저장하므로 `payload->>'licenseNum'`이 field를 text로 추출합니다. [`Pqs.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/pqs/Pqs.java)의 `activeWhere()` method는 이 `WHERE` clause를 `active()` table-valued function에 추가해 `licenseNum`이 일치하는 `LicenseComment` contract만 반환합니다.

### Step 5: REST Endpoint 추가

[`LicenseApiImpl.java`](https://github.com/digital-asset/cn-quickstart/blob/main/quickstart/backend/src/main/java/com/digitalasset/quickstart/service/LicenseApiImpl.java)에 두 method를 추가합니다. Gradle build가 update된 OpenAPI spec에서 `LicensesApi`를 다시 생성하면 두 새 interface method를 구현할 때까지 `LicenseApiImpl`은 compile되지 않습니다. 두 method 모두 authenticate, data lookup, execute, response return이라는 기존 pattern을 따릅니다.

**comment list** — caller를 authenticate하고 license를 lookup해 `licenseNum`을 가져온 다음 PQS에 일치하는 comment를 query합니다.

```java
@Override
@WithSpan
public CompletableFuture<ResponseEntity<List<LicenseComment>>> listLicenseComments(
        String contractId) {
    var ctx = tracingCtx(logger, "listLicenseComments", "contractId", contractId);
    return auth.asAuthenticatedParty(party -> traceServiceCallAsync(ctx, () ->
            damlRepository.findLicenseById(contractId).thenCompose(optLicense -> {
                var license = ensurePresent(optLicense,
                    "License not found for contract %s", contractId);
                return damlRepository.findCommentsByLicenseNum(
                        license.payload.getLicenseNum.intValue())
                    .thenApply(comments -> {
                        var result = comments.stream()
                            .map(LicenseApiImpl::toLicenseCommentApi)
                            .toList();
                        return ResponseEntity.ok(result);
                    });
            })
    ));
}
```

**comment 추가** — caller를 authenticate하고 license를 lookup한 다음 ledger에 `LicenseComment` contract를 생성합니다.

```java
@Override
@WithSpan
public CompletableFuture<ResponseEntity<Void>> addLicenseComment(
        String contractId, String commandId, AddCommentRequest request) {
    var ctx = tracingCtx(logger, "addLicenseComment",
            "contractId", contractId, "commandId", commandId);
    return auth.asAuthenticatedParty(party -> traceServiceCallAsync(ctx, () ->
            damlRepository.findLicenseById(contractId).thenCompose(optLicense -> {
                var license = ensurePresent(optLicense,
                    "License not found for contract %s", contractId);
                var now = Instant.now();
                var comment = new quickstart_licensing.licensing
                        .licensecomment.LicenseComment(
                    license.payload.getProvider,
                    license.payload.getUser,
                    license.payload.getLicenseNum,
                    new Party(party),
                    request.getBody(),
                    now
                );
                return ledger.create(comment, commandId)
                    .thenApply(v -> ResponseEntity.status(HttpStatus.CREATED)
                        .<Void>build());
            })
    ));
}
```

fully-qualified type name인 `quickstart_licensing.licensing.licensecomment.LicenseComment`에 유의하세요. 이는 Daml에서 생성한 class이며 REST response가 사용하는 OpenAPI 생성 `org.openapitools.model.LicenseComment`와 다릅니다. field accessor인 `license.payload.getProvider`와 `license.payload.getLicenseNum`은 getter method가 아니라 transcode로 생성한 class의 public final field입니다.

두 `LicenseComment` type 사이에서 Daml contract인 PQS에서 읽은 항목을 JSON으로 반환하는 API model에 매핑하는 converter method도 필요합니다.

```java
private static LicenseComment toLicenseCommentApi(
        Contract<quickstart_licensing.licensing.licensecomment.LicenseComment> contract) {
    var p = contract.payload;
    var api = new LicenseComment();
    api.setContractId(contract.contractId.getContractId);
    api.setProvider(p.getProvider.getParty);
    api.setUser(p.getUser.getParty);
    api.setLicenseNum(p.getLicenseNum.intValue());
    api.setCommenter(p.getCommenter.getParty);
    api.setBody(p.getBody);
    api.setCreatedAt(toOffsetDateTime(p.getCreatedAt));
    return api;
}
```

이는 file에 이미 있는 `toLicenseApi()`와 같은 pattern입니다. write path는 위 [Command Submission](#creating-a-contract) section에서 본 것과 같은 `ledger.create()` method를 사용합니다. read path는 `DamlRepository`를 통해 PQS를 query하여 read와 write를 분리합니다.
