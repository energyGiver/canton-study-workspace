### SQL로 "Contract Created" Event Stream을 모방하는 방법

PQS는 Ledger API event stream의 적절한 대안이 아니지만 PQS database에서 직접 "contract created" event stream을 가져오는 것이 정당한 경우도 있습니다.

이러한 stream을 모방하려면 유사한 query를 사용해 database에 대한 client-side busy polling을 구현해야 합니다.

<ExternalScribeMainScribeRstCodeDocsUserSdlcHowtosApplicationsDevelopPqsIndexSql175 />

client driver는 이 query를 loop에서 실행하며 마지막으로 관찰한 offset을 memoize[^4]하고 다음 iteration에 전달해야 합니다. result가 반환되지 않을 때 resource 낭비를 최소화하려면 loop에 sleep interval을 추가하는 것이 좋을 수 있습니다.

하지만 latency와 scalability에 엄격한 requirement가 있다면 Ledger API에서 ledger event를 직접 가져오는 것이 가장 좋습니다. PQS는 event stream을 제공하기보다 특정 offset의 ledger *state*를 query하기 위한 Ledger API Transaction stream의 complementary source로 사용하는 데 가장 적합하도록 설계되었습니다.

## Optimize

PQS는 PostgreSQL database를 기반으로 합니다. 모든 query optimization은 본질적으로 database/SQL tuning concern입니다. 일반적인 SQL development best practice가 적용됩니다.

- 자주 사용하는 clause에 index 적용
- data fetching 제한, final projection에서 불필요한 column을 제거하고 `SELECT *` 사용 방지
- 읽기 쉬운 Daml model design
- `OFFSET` SQL clause를 사용한 pagination 방지
- 가능하면 `SELECT COUNT(*)`와 유사한 query 사용 방지

performance optimization에 관한 추가 information은 [Performance Optimization](/appdev/deep-dives/performance-optimization)을 참고하세요.
