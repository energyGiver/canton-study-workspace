Canton node는 static configuration file에 [HOCON](https://github.com/lightbend/config/blob/master/HOCON.md), Human-Optimized Config Object Notation을 사용합니다. Static configuration은 storage backend, API port, node identity처럼 process startup 시점에 알아야 하는 setting을 다룹니다. Party registration, synchronizer connection과 같은 dynamic setting은 runtime에 [console](/global-synchronizer/reference/canton-console-reference) 또는 administration API를 통해 관리합니다.

## HOCON 기본 Format

HOCON은 더 유연한 quoting, nested key path인 `a.b.c = value`, `//` 또는 `#` comment를 지원하는 JSON과 비슷한 object syntax를 제공합니다. 반복 key는 merge되며 마지막 definition이 우선합니다.

### Environment Variable Substitution

HOCON은 `${VAR_NAME}` syntax로 environment variable을 substitution합니다. 두 가지 형식을 사용할 수 있습니다.

- `${VAR_NAME}` -- required입니다. Variable이 설정되지 않으면 process가 start하지 못합니다.
- `${?VAR_NAME}` -- optional입니다. Variable이 존재할 때만 key가 설정됩니다.

## Storage Configuration

Canton은 세 가지 storage backend를 지원합니다.

- **Memory** -- 빠른 test용이며 restart하면 data가 사라집니다.
- **H2** -- local development에 적합한 embedded database입니다.
- **PostgreSQL** -- production에 지원되는 유일한 option입니다.

### PostgreSQL 예시

각 Canton node는 자신만의 database가 필요합니다. UTF-8 encoding으로 database를 생성하세요.

```sql
CREATE DATABASE participant1_db ENCODING = 'UTF8';
CREATE USER participant1_user WITH PASSWORD 'change-me';
GRANT ALL PRIVILEGES ON DATABASE participant1_db TO participant1_user;
```

Canton은 connection pooling에 [HikariCP](https://github.com/brettwooldridge/HikariCP)를 사용합니다. `storage.config`에서 pool property인 `maximumPoolSize`, `connectionTimeout`, `idleTimeout` 등을 tuning할 수 있습니다.

### Configuration Mixin Pattern

여러 node를 같은 database server에서 실행할 때는 shared storage setting을 mixin에 define하고 node별로 reference하세요.

## DPM Project Configuration

DPM은 Canton의 HOCON node configuration과 별개로 project configuration에 YAML file을 사용합니다.

### daml.yaml, Single Package

각 Daml package의 `daml.yaml`은 SDK version, package name, source directory, dependency를 지정합니다.

### multi-package.yaml, Multi-Package Project

Multi-package project configuration은 `multi-package.yaml` structure와 dependency resolution을 다루는 [Building and Packaging](/appdev/modules/m3-building-packaging)을 참고하세요.

### DPM Environment Variable

DPM environment variable의 세부 사항은 [Building and Packaging](/appdev/modules/m3-building-packaging)을 참고하세요.

### DPM Global Configuration

DPM은 `${DPM_HOME}/dpm-config.yaml`에서 global setting을 읽습니다. Environment variable은 file value보다 우선합니다.

- `DPM_REGISTRY` -- SDK 및 component의 Docker registry를 override합니다.
- `DPM_REGISTRY_AUTH` -- registry auth file을 override합니다.
- `DPM_INSECURE_REGISTRY` -- HTTP registry에서 pulling을 허용합니다.
- `DPM_LOG_LEVEL` -- log level을 설정합니다. 가능한 value는 `debug`, `info`, `warn`, `error`입니다.
- `DPM_SDK_VERSION` -- 모든 project에서 SDK version을 global override합니다.
- `DAML_PACKAGE` -- directory를 변경하지 않고 package context에서 `dpm` command을 실행합니다.
