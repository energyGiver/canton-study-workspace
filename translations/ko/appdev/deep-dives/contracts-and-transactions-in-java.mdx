# Java에서 contract와 Transaction을 사용하는 방법

Java로 Canton Network application을 작성할 때는 원래 Daml code와 매우 유사하면서도 가능한 한 Java native type에 가까운 Daml template 및 data type 표현을 Java에서 사용하면 편리합니다. 이를 위해 Daml Codegen for Java를 사용하여 Daml model을 기반으로 Java type을 생성합니다. 그러면 ledger에서 정보를 읽고 ledger로 data를 보낼 때 Java code에서 이러한 type을 사용할 수 있습니다.

## Codegen 설정

Daml Codegen for Java의 안내에 따라 Java code generator를 실행하고 구성하여 project에서 사용할 Java class를 생성합니다.

Daml built-in type과 user-defined type에 대해 생성된 code가 어떤 모습인지 Generated code에서도 확인하세요.

## Project에서 생성된 class 사용

생성된 Java class를 compile하려면 build tool에 Java bindings library를 dependency로 추가해야 합니다.

## Java bindings를 사용하여 gRPC Ledger API에 접근

`bindings-java` library에는 Ledger API에 접근할 수 있도록 생성된 gRPC stub이 함께 package되어 있습니다.

각 Ledger API service마다 이름이 일치하는 전용 Java class가 있습니다. 예를 들어 `CommandSubmissionService`의 gRPC counterpart는 `CommandSubmissionServiceGrpc`입니다.

### Ledger에 연결

Ledger에 연결하고 Ledger API service에 접근하려면 `ManagedChannel` instance를 생성합니다. 이때 static `NettyChannelBuilder.forAddress(..)` method를 사용합니다. 그런 다음 해당 service의 factory method, 예를 들어 `CommandSubmissionServiceGrpc.newFutureStub`을 호출하여 stub을 생성합니다. `bindings-java`가 제공하는 helper class 중 하나를 사용하여 service request argument를 나타내는 object를 생성하고 proto message로 변환합니다. 마지막으로 service에서 제공하는 원하는 method를 호출합니다.

```java
// Create a managed channel object pointing to the Ledger API address.
ManagedChannel channel = NettyChannelBuilder.forAddress(host, port).usePlaintext().build();

// Create a stub connecting to the desired service on the ledger.
CommandSubmissionServiceFutureStub submissionService = CommandSubmissionServiceGrpc.newFutureStub(channel);

// Create an object representing the service call arguments
CommandsSubmission commandsSubmission = CommandsSubmission.create(...);

// Convert the command submission to a proto data structure
final var request = SubmitRequest.toProto(commandsSubmission);

// Issue the service call
final var response = submissionService.submit(request)
```

### Authorization 수행

일부 ledger는 authorization을 강제하며 각 request와 함께 access token을 보내야 합니다. Authorization에 대한 자세한 내용은 Authorization overview를 참조하세요.

모든 Ledger API request에 같은 token을 사용하려면 service stub class의 `withCallCredentials` method를 사용합니다. 이 method는 `CallCredentials`에서 파생된 class를 argument로 받습니다. Header에 token을 제공하는 자체 파생 class를 구현하세요.

```java
public final class LedgerCallCredentials extends CallCredentials {

    private static Metadata.Key<String> header =
            Metadata.Key.of("Authorization", Metadata.ASCII_STRING_MARSHALLER);

    private final String token;

    public LedgerCallCredentials(String token) {
        super();
        this.token = token;
    }

    @Override
    public void applyRequestMetadata(
            RequestInfo requestInfo, Executor appExecutor, MetadataApplier applier) {
        Metadata metadata = new Metadata();
        metadata.put(LedgerCallCredentials.header, token.startsWith("Bearer ") ? token : "Bearer " + token);
        applier.apply(metadata);
    }
}
```

Application이 장시간 실행되고 token이 만료되도록 설정되어 있다면 필요할 때 token을 다시 load하고 모든 call에서 명시적으로 전달합니다.

Authorization을 검증하는 ledger와 통신할 때는 man-in-the-middle attack으로 token이 노출되지 않도록 communication channel을 보호하는 것이 매우 중요합니다. 다음 section에서는 TLS를 활성화하는 방법을 설명합니다.

### 안전하게 연결

`NettyChannelBuilder.forAddress`로 생성하는 builder는 기본적으로 TLS connection을 사용하며 key는 구성된 Java Keystore에서 가져옵니다. 자체 cryptographic setting을 제공하여 이 동작을 override할 수 있습니다. 이렇게 하려면 `sslContext`를 호출하고 `SslContext`를 전달합니다.

```java
NettyChannelBuilder.forAddress(host, port)
            .useTransportSecurity()
            .sslContext(sslContext)
            .build();
```

<Warning>
`usePlaintext()`를 호출하여 plaintext connection을 구성할 수도 있습니다. 개발 목적으로 local에서 실행 중인 ledger에 연결할 때만 사용하세요.
</Warning>

Ledger에 대한 secure connection은 client authentication certificate를 사용하도록 구성해야 하며, 이 certificate는 ledger operator가 제공할 수 있습니다.

제공된 client authentication certificate로 `SslContext`를 설정하는 방법은 OpenSSL을 사용하는 TLS에 관한 gRPC documentation과 `grpc-java` project의 HelloWorldClientTls example을 참조하세요.

## Asynchronous stub 사용

Ledger API gRPC service를 위해 생성되는 class에는 blocking, future-based, asynchronous의 여러 유형이 있습니다. 마지막 유형이 gRPC layer와 interaction하는 권장 방식입니다. 위에서 사용한 `CommandService` 예시에서는 각각 `CommandServiceBlockingStub`, `CommandServiceFutureStub`, `CommandServiceStub`이라고 합니다.

Java application에서 호출하려는 각 gRPC endpoint에 대해 `onNext`, `onError`, `onComplete` observer method 구현을 제공하는 gRPC StreamObserver를 생성합니다. gRPC message를 decode하고 encode하려면 Java bindings library의 생성 class에서 `fromProto` 및 `toProto` method를 사용합니다.

### OpenAPI definition 사용

OpenAPI definition은 각 Ledger API service의 definition을 제공하며 JSON Ledger API를 통해 접근할 수 있게 합니다. 이 definition을 사용하여 JSON Ledger API가 요구하는 JSON payload로 gRPC message를 encode하거나 JSON payload에서 decode합니다. 자세한 내용은 Canton 및 JSON Ledger API 시작하기를 참조하세요.
